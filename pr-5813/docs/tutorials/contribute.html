Contribute a tutorial

Qiskit tutorials on IBM Quantum® Platform are open to community contributions. This page explains which tutorials you can contribute, what each kind of tutorial must show, and how to propose one.

Every tutorial belongs to a domain (optimization, Hamiltonian simulation, quantum machine learning, or quantum information science) and is either Foundational or Applied:

  • Foundational tutorials teach the core ideas and canonical methods of a domain. They use well-known teaching problems, so that the method is the focus rather than the problem.
  • Applied tutorials are built around a specific goal: solving a particular problem from the problem classes on this page, or applying a specialized technique or tool in the setting where it can be used successfully. They assume strong familiarity with the fundamentals.

In short, Foundational tutorials show how to use a method or tool, and Applied tutorials show the best current results on a specific problem.

Requirements

Every tutorial must:

  • Follow the tutorial template, use current Qiskit with no deprecated interfaces, and cover something that IBM Quantum Learning courses and existing tutorials do not.
  • Use only the approved quantum packages, including Qiskit Functions, pin every package version, and keep custom code in the notebook.
  • Verify a small instance against a known answer (exact, analytic, or published) within a stated tolerance before scaling up.
  • Run on IBM Quantum hardware at about 50 qubits or more, and report the error mitigation settings and QPU time.

Beyond these, Foundational and Applied tutorials differ in what they cover and the bar they meet:

  • Foundational tutorials teach how to use a method or tool on the domain's foundational problem class, show its trade-offs against a default approach, and link to the Applied work that the method leads to.
  • Applied tutorials solve a real instance from a problem class, or, in quantum information science, apply a specialized technique at scale. They compare against a classical method and meet a state-of-the-art bar.

For the detailed requirements and how reviewers check them, see the guide to adding tutorials.

How to propose a tutorial

Contributions go through two stages, so that you get feedback before you write the full tutorial.

  1. Propose. Open a tutorial proposal issue in the Qiskit documentation repository. The IBM Quantum tutorials team and a member of the relevant working group review it against these requirements.
  2. Submit. After your proposal is approved, open a pull request from your fork that adds the notebook, and sign the Contributor License Agreement.

To improve an existing tutorial, propose the improvement the same way. The guide to adding tutorials describes the review process and how to add your notebook.

Authorship

  • Credit. Your tutorial shows a byline with the authors' names and affiliations and a link to the source paper, and its tutorial card shows a community tag.
  • Ongoing maintenance. A maintainer of record from the IBM Quantum team keeps the tutorial running as Qiskit changes.
