# Contribute a tutorial

Qiskit tutorials on IBM Quantum&reg; Platform are open to community contributions. This page explains which tutorials you can contribute, what each kind of tutorial must show, and how to propose one.

Every tutorial belongs to a domain (optimization, Hamiltonian simulation, quantum machine learning, or quantum information science) and is either Foundational or Applied:

- **Foundational tutorials** teach the core ideas and canonical methods of a domain. They use well-known teaching problems, so that the method is the focus rather than the problem.
- **Applied tutorials** are built around a specific goal: solving a particular problem from the working-group problem classes, or applying a specialized technique or tool in the setting where it can be used successfully. They assume strong familiarity with the fundamentals.

## What you can contribute

| Domain | Foundational tutorials | Applied tutorials |
| --- | --- | --- |
| [Optimization](#optimization) | Open, for a listed topic | Open, for a problem class |
| [Hamiltonian simulation](#hamiltonian-simulation) | Open, for a listed topic | Open, for a problem class |
| [Quantum machine learning](#quantum-machine-learning) | Open, for a listed topic | Open, for a problem class |
| [Quantum information science](#quantum-information-science) | Open, for a listed topic | Written by the IBM Quantum team |

The following are out of scope:

- Applied quantum information science tutorials, which usually build on IBM tools in active development.
- Content that duplicates an [IBM Quantum Learning](/learning) course or an existing tutorial. To improve an existing tutorial, open a pull request against it instead.

## Requirements for all tutorials

Every contributed tutorial must meet these requirements:

- **Follows the tutorial template.** Include a usage estimate, learning outcomes, prerequisites, and the Qiskit patterns steps (map, optimize, execute, and post-process).
- **Uses current Qiskit.** Use current Qiskit patterns and primitives, with no deprecated interfaces.
- **Uses accepted dependencies.** Quantum software must come from the [Qiskit organization on GitHub](https://github.com/Qiskit), such as the Qiskit SDK, Qiskit Runtime, and the Qiskit addons, or from the [Qiskit ecosystem](https://www.ibm.com/quantum/ecosystem). An ecosystem package must support the current Qiskit release and have a release from the past 12 months, and you must name it in your proposal so that reviewers can approve it. Install all packages from PyPI with pinned versions, and put any custom code in the notebook rather than in a separate repository.
- **Verifies a small instance.** Before you scale up, run a small instance and show that it matches a known answer (from exact diagonalization, an exact solver, an analytic result, or a published reference) within a tolerance that the tutorial states.
- **Runs on hardware.** Run the workload on IBM Quantum hardware through the Qiskit Runtime primitives. State the error suppression and mitigation settings, and report the QPU time.

## Requirements for Foundational tutorials

A Foundational tutorial teaches a method that readers then use in Applied work, so it must be useful beyond a single example.

- **Fills an open topic.** Cover one of the open topics listed for your domain in [Open topics and problem classes](#open-topics-and-problem-classes).
- **Uses the teaching problem.** Run the method on the teaching problem listed for your domain or topic, so that the method stays the focus.
- **Leads to Applied work.** The method must be a step in the Applied tutorial or problem class listed for your topic. Link to it in a "Next steps" section, and explain which step your tutorial prepares readers for.
- **Goes beyond a course.** Link to IBM Quantum Learning for the theory instead of repeating it, and focus on running the method on hardware.
- **Scales up.** After the small, verified instance, run the same workflow on hardware at about 50 qubits or more.
- **Shows the trade-offs.** Show how cost, noise sensitivity, or accuracy changes as the problem grows, and compare against a default or naive approach.
- **Uses open-source tools only.** Use no Qiskit Functions or licensed tools, so that readers can reuse the code in their own workflows.

Reviewers check every Foundational proposal against three questions. A proposal must answer yes to all three:

1. Does it cover an open topic, or a gap that reviewers agree to add as one?
2. Is the method it teaches a step in the Applied tutorial or problem class listed for its topic?
3. Does it show something on hardware that a course does not, such as a run at about 50 qubits or a trade-off?

## Requirements for Applied tutorials

An Applied tutorial is a reference implementation of a state-of-the-art result, so it has a higher bar.

- **State of the art.** The tutorial meets at least two of the following criteria:
  - It is based on a paper published in a peer-reviewed journal within the past three years.
  - It is the largest hardware demonstration of its problem.
  - It uses advanced features, such as dynamic circuits or shaded lightcones.
- **Tied to a problem class.** The tutorial solves a real instance from one of the [problem classes](#open-topics-and-problem-classes) and reports that class's target quantity. Each class accepts one community tutorial per method family. A new tutorial in a method family that already has one replaces it only if it reaches larger scale at the same accuracy, better accuracy at the same scale, or much lower QPU cost.
- **At scale.** The hardware run uses at least 50 qubits and a two-qubit depth of at least 50. A smaller run is acceptable only if the tutorial clearly meets the state-of-the-art bar.
- **Reproducible.** Anyone can run the notebook unchanged on a current-generation IBM Quantum backend and get results within the tutorial's reported error bars.
- **Compared against a classical baseline.** Report a classical method on the same instance, even when it performs better. For example, use an exact or heuristic solver for optimization, a tensor network method for Hamiltonian simulation, or a classical model with the same data split and metric for quantum machine learning.

## Open topics and problem classes

For each domain, this section lists the teaching problem and open topics for Foundational tutorials, and the problem classes for Applied tutorials. The working groups use these problem classes to track progress toward quantum advantage. To propose a topic or problem class that is not listed, open a [proposal](#how-to-propose-a-tutorial) and explain the gap it fills.

### Optimization

Foundational tutorials use max-cut as the teaching problem. No Foundational topics are open yet.

Applied tutorials target one of the ten problem classes in the [Quantum Optimization Benchmarking Library (QOBLIB)](https://arxiv.org/abs/2504.03832):

| Problem class | Description |
| --- | --- |
| Market split | Multi-dimensional subset sum |
| Low autocorrelation binary sequences | Radar and communications sequence design |
| Minimum Birkhoff decomposition | Doubly stochastic matrix decomposition |
| Steiner tree packing | VLSI design and wire routing |
| Sports tournament scheduling | Constraint satisfaction |
| Portfolio optimization | Multi-period portfolios with transaction costs and short selling |
| Maximum independent set | Unweighted maximum independent set on graphs |
| Network design | Telecommunications network planning |
| Vehicle routing | Vehicle routing with time windows and knapsack constraints |
| Topology design | Graph golf (the degree-diameter problem) |

### Hamiltonian simulation

Foundational tutorials use one of two teaching problems: the N<sub>2</sub> molecule in a minimal basis for chemistry, or the one-dimensional Heisenberg or Ising chain for spin and lattice models. No Foundational topics are open yet.

Applied tutorials target one of the following problem classes. These classes are a draft proposal for the Hamiltonian Simulation Working Group and might change.

| Problem class | Target quantity |
| --- | --- |
| Strongly correlated molecular ground states | Ground-state energy across geometries |
| Nuclear shell-model ground states | Ground-state energy |
| Electron-phonon dynamics | Polaron quench dynamics |
| Lattice gauge real-time dynamics | String-breaking and hadron dynamics |
| SYK scrambling (long-term target) | Out-of-time-order correlators and spectral form factor |
| Frustrated magnets | Ground-state and finite-temperature observables |
| Kicked and Floquet spin dynamics | Quench observables |
| Symmetric spin dynamics | Dynamical structure factor |
| Doped 2D Fermi-Hubbard dynamics | Charge and spin quench dynamics |
| Quantum impurity models | Impurity Green's function |

### Quantum machine learning

Foundational tutorials use a small classification dataset with a classical baseline as the teaching problem. One Foundational topic is open:

| Open topic | Leads to |
| --- | --- |
| Training and evaluating a quantum kernel classifier on a small dataset, with a classical baseline | Classification problem classes |

Applied tutorials target one of the following problem classes. These classes are a draft proposal for the Quantum Machine Learning Working Group and might change.

| Problem class | Target quantity |
| --- | --- |
| Quantum phase classification | Test accuracy versus sample count |
| Quantum property prediction | Samples needed to reach a target error |
| Hamiltonian learning | Parameter error versus samples |
| Generative learning of hard distributions | Sampling fidelity or cross-entropy |
| Group-structured classification | Test accuracy |
| Quantum reservoir and extreme learning | Prediction error or test accuracy |
| Real-world tabular classification | Accuracy versus a matched classical model |

### Quantum information science

Quantum information science has no problem classes, and its Applied tutorials are written by the IBM Quantum team. Foundational tutorials are open for the following topics only, and each topic names its own teaching problem.

| Open topic | Teaching problem | Leads to |
| --- | --- | --- |
| Phase estimation at scale without vendor tools, for example iterative phase estimation with dynamic circuits | The one-dimensional transverse-field Ising chain, whose energies are known exactly | Energy estimation in Hamiltonian simulation |
| Device benchmarking with cross-entropy benchmarking and random circuit sampling | Random circuits, simulated exactly at small sizes | Quantum advantage experiments |
| Error correction beyond the repetition code, such as syndrome extraction with dynamic circuits | A small stabilizer code, such as the Steane code or the distance-3 surface code | [Low-overhead error detection with spacetime codes](/docs/tutorials/spacetime-codes) |
| Fidelity estimation and certification of large entangled states | GHZ and graph states | Learning and certifying quantum states |

## How to propose a tutorial

Contributions go through two stages, so that you get feedback before you write the full tutorial.

1. **Propose.** Open a [tutorial proposal issue](https://github.com/Qiskit/documentation/issues/new?template=tutorial-proposal.yaml) in the Qiskit documentation repository. Proposals are public, so you can check what others are already working on. The IBM Quantum tutorials team reviews each proposal against these requirements, and a member of the relevant working group reviews the technical content.
2. **Submit.** After your proposal is approved, open a pull request from your fork that adds the notebook. Follow the [contributing guide](https://github.com/Qiskit/documentation/blob/main/CONTRIBUTING.md), including signing the [Contributor License Agreement](https://qisk.it/cla).

## Authorship and maintenance

- **Credit.** Contributed tutorials show a byline at the top with the authors' names and affiliations and a link to the source paper. Tutorial cards show a community tag.
- **Maintainer of record.** Each contributed tutorial also has a maintainer of record from the IBM Quantum team, who keeps it running as Qiskit changes.
- **Breaking changes.** If a change breaks the tutorial, the authors have 30 days to respond to the issue. If it is still unresolved after the next major Qiskit release, the tutorial is archived.
- **Existing community tutorials.** These requirements apply to new contributions. Community tutorials that are already published get the community tag, and are held to these requirements when they are next updated.
