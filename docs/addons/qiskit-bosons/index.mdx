# Qiskit Bosons

`qiskit-bosons` extends the Qiskit SDK with tools for working on bosonic systems. Within its scope it provides the following:

*   An efficient data structure for the representation and manipulation of bosonic operators
*   A framework for implementing boson-to-qubit encodings, built around shared level encodings (unary with or without projectors, standard binary, Gray), and a library of common mappers
*   A framework and library of gates for expressing bosonic circuits
*   A transpilation pipeline integrated with the Qiskit transpiler process to synthesize bosonic circuits into qubit-based circuits

## Get started

This package covers the whole path from a bosonic operator to a qubit circuit. You can work in the bosonic regime with both, operator and circuit representation, before you choose a truncation and a boson-to-qubit encoding that plug into the multi-representation transpiler pipeline of Qiskit.

All of these features are explained in [several guides](/docs/addons/qiskit-bosons/guides/overview) to help you get started. For an end-to-end overview, start with the [Bose-Hubbard guide](/docs/addons/qiskit-bosons/guides/bose-hubbard).

## Technical discussion

### Design intentions

This package is deliberately designed to align with Qiskit: it builds on a core implemented in Rust and provides first-party language bindings to Python. Its API intends to draw parallels to Qiskit in order to seamlessly integrate into the workflows of users with experience in programming Qiskit. While there exists no C API right now, the architecture is set up to support one if the need for one ever arises in the future. The architecture of this package is also deliberately analogous to that of [qiskit-fermions](https://github.com/Qiskit/qiskit-fermions).

A core principle to the design of `qiskit-bosons` was the decoupling of its bosonic circuit representation from its qubitized form. To be more precise: the bosonic circuits are meaningful by themselves and do not require a mapping to qubit space to be interpretable. Furthermore, the bosonic circuit representation cannot make any assumptions about the truncation and boson-to-qubit encoding applied later on. Both enter only at transpile time.

## Deprecation policy

We follow [semantic versioning](https://semver.org/) and are guided by the principles in [Qiskit’s deprecation policy](https://github.com/Qiskit/qiskit/blob/main/DEPRECATION.md). We may occasionally make breaking changes in order to improve the user experience. When possible, we will keep old interfaces and mark them as deprecated, as long as they can co-exist with the new ones. Each substantial improvement, breaking change, or deprecation will be documented in the [release notes](/docs/api/qiskit-bosons/release-notes).
