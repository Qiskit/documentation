# Q-CTRL Dynamics Simulator API reference

<Admonition type="caution">
  Dynamics Simulator accepts a physical model description rather than circuits. Fire Opal builds and optimizes the circuits for the target backend, so do not transpile or pre-compile anything.
</Admonition>

## Inputs

See the following list for all input parameters that this API accepts. All inputs are passed as keyword arguments. `model`, `simulation`, and `observables` can each be given either as a Python dictionary (list of dictionaries for `observables`) or as a JSON string. The function rejects unknown top-level arguments.

### `model`

<Attribute attributeTypeHint="dict[str, Any] or str">
The Fermi-Hubbard model, given as a dictionary or a JSON string. See [Model fields](#model-fields) for the fields it contains.
- Required: Yes
- Example: `{"hopping_amplitude": 1.0, "on_site_interaction": [2.0, 2.5, 2.0], "chemical_potential": 0.5}`
</Attribute>

#### Model fields

<LeftColoredBar color="blue">
    `hopping_amplitude`
        <Attribute attributeTypeHint="float or list[float]">
        Tunneling amplitude. A scalar is broadcast across all bonds. A list must have `len(initial_state) - 1` entries (one per bond).
        </Attribute>

    `on_site_interaction`
        <Attribute attributeTypeHint="float or list[float]">
        On-site interaction strength. A scalar is broadcast across all sites. A list must have `len(initial_state)` entries (one per site).
        </Attribute>

    `chemical_potential`
        <Attribute attributeTypeHint="float or list[float]">
        Chemical potential. A scalar is broadcast across all sites. A list must have `len(initial_state)` entries (one per site).
        </Attribute>
</LeftColoredBar>

### `simulation`

<Attribute attributeTypeHint="dict[str, Any] or str">
The Trotter simulation scheme, given as a dictionary or a JSON string. See [Simulation fields](#simulation-fields) for the fields it contains.
- Required: Yes
- Example: `{"method": "trotter", "step_count": 5, "time_step": 0.1}`
</Attribute>

#### Simulation fields

<LeftColoredBar color="blue">
    `method`
        <Attribute attributeTypeHint="str">
        Simulation method. `"trotter"` is the supported method.
        - Choices: `trotter`
        </Attribute>

    `step_count`
        <Attribute attributeTypeHint="int">
        Number of Trotter steps.
        </Attribute>

    `time_step`
        <Attribute attributeTypeHint="float">
        Duration of each Trotter step.
        </Attribute>
</LeftColoredBar>

### `observables`

<Attribute attributeTypeHint="list[dict[str, Any]] or str">
The sparse occupation operators to measure, one dictionary per observable, given as a list of dictionaries or a JSON string. Must contain at least one observable. See [Observable fields](#observable-fields) for the fields each dictionary contains.
- Required: Yes
- Example: `[{"operators": [[["Nup", 0]]], "coefficients": [1.0]}]`
</Attribute>

#### Observable fields

<LeftColoredBar color="blue">
    `operators`
        <Attribute attributeTypeHint="list[list[list[str, int]]]">
        The terms of the observable. Each term is a product of `[operator_name, site_index]` pairs, where `operator_name` is `"Nup"` or `"Ndn"`.
        </Attribute>

    `coefficients`
        <Attribute attributeTypeHint="list[float]">
        One coefficient per term in `operators`.
        </Attribute>
</LeftColoredBar>

### `initial_state`

<Attribute attributeTypeHint="str">
The initial Fock state, with one character per lattice site. Must be non-empty. The number of lattice sites is `len(initial_state)`, and the simulation uses `2 * len(initial_state)` qubits. The backend must have at least that many qubits.
- Required: Yes
- Allowed characters:
  * `"e"`: (empty) unoccupied site 
  * `"u"`: (up) singly occupied, spin up 
  * `"d"`: (down) singly occupied, spin down 
  * `"b"`: (both) doubly occupied 
- Example: `"udb"`
</Attribute>

### `shots`

<Attribute attributeTypeHint="int">
The number of shots to use for each circuit execution. Must be a positive integer.
- Required: Yes
- Example: `1000`
</Attribute>

### `backend_name`

<Attribute attributeTypeHint="str" attributeValue="Automatic selection">
Name of the backend to use. If you don't provide a name, the function automatically selects a backend with enough qubits.
- Required: No
- Example: `"ibm_phoenix"`
</Attribute>

### Options

<Attribute attributeTypeHint="dict" attributeValue="{}">
Additional run options, passed as `options`. Options are specified as a nested dictionary. See the [options list](#options-list) for details and default values.
- Required: No
- Example: `{"job_tags": ["my_tag"]}`
</Attribute>

<span id="options-list"></span>
#### Options list

##### `session_id`

<Attribute attributeTypeHint="str" attributeValue='""'>
An existing IBM Quantum Compute Service session ID.
- Example: `"cw4r3je6f0t010870y3g"`
</Attribute>

##### `job_tags`

<Attribute attributeTypeHint="list[str]" attributeValue="[]">
A list of job tags.
- Example: `["job_tag1", "job_tag2"]`
</Attribute>

## Outputs

The output of this API is a `dict` that contains the simulation results and metadata. The results include the expectation values of the requested observables at every time step of the Trotterized time evolution.

<Attribute attributeTypeHint="dict[str, Any]">
The simulation results and metadata listed under [Output structure](#output-structure).
- Example: `{"observable_expectation_values": [ [1.0, 0.96, 0.91],[0.0, 0.04, 0.08]], "observables": [{"operators": [[["Nup", 0]]],"coefficients": [1.0]}], "warnings": [], "metadata": {}}`
</Attribute>

### Output structure

<LeftColoredBar color="blue">
    `observable_expectation_values`
        <Attribute attributeTypeHint="list[list[float]]">
        Expectation values, one list per input observable, in the same order as `observables`. Each list contains `step_count + 1` values, including the initial state.
        </Attribute>

    `observables`
        <Attribute attributeTypeHint="list[dict[str, Any]]">
        The observables that were measured, echoed back from the input.
        </Attribute>

    `warnings`
        <Attribute attributeTypeHint="list[str]">
        Warnings produced while compiling or running the simulation.
        </Attribute>

    `metadata`
        <LeftColoredBar color="purple">
            `resource_usage`
                <Attribute attributeTypeHint="dict">
                A breakdown of CPU and QPU time (in seconds) for each stage of the run. Each stage has a `CPU_TIME` and a `QPU_TIME`.
                    <LeftColoredBar color="purple">
                        `RUNNING: MAPPING`
                        <Attribute attributeTypeHint="dict">
                        Mapping the problem to the device.
                        </Attribute>

                        `RUNNING: OPTIMIZING_HARDWARE`
                        <Attribute attributeTypeHint="dict">
                        Optimizing the circuits for the hardware.
                        </Attribute>

                        `RUNNING: WAITING_QPU`
                        <Attribute attributeTypeHint="dict">
                        Time spent waiting on the QPU queue (CPU time).
                        </Attribute>

                        `RUNNING: EXECUTING_QPU`
                        <Attribute attributeTypeHint="dict">
                        Time executing on the QPU (QPU time).
                        </Attribute>

                        `RUNNING: POST_PROCESSING`
                        <Attribute attributeTypeHint="dict">
                        Post-processing of results.
                        </Attribute>
                    </LeftColoredBar>
                </Attribute>
        </LeftColoredBar>
</LeftColoredBar>
