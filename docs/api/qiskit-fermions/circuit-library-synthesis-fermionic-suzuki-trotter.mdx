# FermionicSuzukiTrotter

<Class id="qiskit_fermions.circuit.library.synthesis.FermionicSuzukiTrotter" isDedicatedPage={true} signature="FermionicSuzukiTrotter(order=2, reps=1)" modifiers="class">
  Bases: [`FermionicEvolutionSynthesis`](circuit-library-synthesis-fermionic-evolution-synthesis "qiskit_fermions.circuit.library.synthesis.evolution_synthesis.FermionicEvolutionSynthesis")

  The higher-order Suzuki-Trotter product formula, applied in fermionic space.

  A product formula composes the factors of an operator symmetrically, so that the leading error terms cancel. For $\texttt{order} = 2$ and factors $H_j$, the approximation is the palindrome

$$
\[e^{-i t \sum_j H_j} \approx
\left( \prod_{j
$$

  where $\mathrm{R}$ denotes the reversed order. Higher even orders are built from this by Suzuki’s recursion, each level composing five sweeps of the level below.

  The evolved operator is split by its [`groups`](operators-operator-trait#groups "qiskit_fermions.operators.OperatorTrait.groups") when it has them (see [Group operator terms: use the operator structure](guides/grouping#grouping-explanation)), and term-by-term otherwise. Every order splits it the same way: what a higher order changes is the ordering of the factors and their time scales, not the partition.

  <Admonition title="Note" type="note">
    A higher order buys accuracy with depth: an order-$k$ formula emits roughly $5^{(k-2)/2}$ times as many factors as an order-2 one. Increasing [`reps`](#qiskit_fermions.circuit.library.synthesis.FermionicSuzukiTrotter.reps "qiskit_fermions.circuit.library.synthesis.FermionicSuzukiTrotter.reps") instead divides the evolution time into more, shorter steps, which reduces the error at a different rate for the same kind of cost. Which is the better trade depends on the operator.
  </Admonition>

  <Admonition title="Note" type="note">
    Applying this in fermionic space at all is optional, and it composes with the product formula chosen for the fermion-to-qubit stage. Where both approximate, the accuracy of the result is governed by the weaker of the two – so raising the order here while the qubit-side formula stays first-order buys little. See [`synthesis`](/docs/api/qiskit-fermions/circuit-library-synthesis#module-qiskit_fermions.circuit.library.synthesis "qiskit_fermions.circuit.library.synthesis").
  </Admonition>

  <Admonition title="Note" type="note">
    Because the factor ordering is part of the formula, a reference value computed with one product formula does not carry over to another. [`UCC.cluster_operator()`](circuit-library-ucc#cluster_operator "qiskit_fermions.circuit.library.UCC.cluster_operator") pins its group order deliberately, assigning indices in sorted key order rather than by first encounter, so that its Trotter error is reproducible; a Suzuki formula then reorders those groups by design. A [`UCC`](circuit-library-ucc "qiskit_fermions.circuit.library.UCC") reference value obtained at `order=1` therefore differs at `order >= 2`, for the same operator and the same [`reps`](#qiskit_fermions.circuit.library.synthesis.FermionicSuzukiTrotter.reps "qiskit_fermions.circuit.library.synthesis.FermionicSuzukiTrotter.reps"). That is inherent to choosing a different product formula rather than a regression, and the default synthesis is unchanged, so nothing moves unless a higher order is requested.
  </Admonition>

  <Admonition title="Caution" type="note">
    Each factor must be Hermitian for its exponential to be unitary, which does not follow from their sum being Hermitian: splitting a Hermitian operator can produce non-Hermitian groups (for example, separating $a^\dagger_0 a_1$ from its conjugate partner $a^\dagger_1 a_0$). It is the caller’s responsibility to group accordingly; this is not verified.

    An operator with no groups is split term by term, which has the same effect, since an individual term is generally not Hermitian. The resulting factors are valid fermionic operators and the gates are built without complaint, but the fermion-to-qubit stage then rejects them: [`PauliEvolutionGate`](/docs/api/qiskit/qiskit.circuit.library.PauliEvolutionGate) requires real coefficients and raises `ValueError: Operator contains complex coefficients, which are not supported`.

    Note that the symmetrization partially cancels the error of a non-Hermitian factor, so an incorrectly grouped operator can look markedly better at an even order than at first order while still being wrong.
  </Admonition>

  Initializing an instance of this synthesis method can be done with the arguments below.

  **Parameters**

  *   **order** ([*int*](https://docs.python.org/3/library/functions.html#int)) – the order of the product formula. Must be `1` (which reduces to [`FermionicLieTrotter`](circuit-library-synthesis-fermionic-lie-trotter "qiskit_fermions.circuit.library.synthesis.FermionicLieTrotter")) or even, since the Suzuki formulas are symmetric.
  *   **reps** ([*int*](https://docs.python.org/3/library/functions.html#int)) – the number of times to repeat the formula, each repetition evolving for `time / reps`.

  **Raises**

  [**ValueError**](https://docs.python.org/3/library/exceptions.html#ValueError) – if `order` is neither `1` nor even, or if `reps` is not positive.
