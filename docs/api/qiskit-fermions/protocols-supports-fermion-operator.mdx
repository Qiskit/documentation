# SupportsFermionOperator

<Class id="qiskit_fermions.protocols.SupportsFermionOperator" isDedicatedPage={true} signature="SupportsFermionOperator(*args, **kwargs)" modifiers="class">
  Bases: [`Protocol`](https://docs.python.org/3/library/typing.html#typing.Protocol)

  This package’s operator-conversion contract, converting an operator to a [`FermionOperator`](operators-fermion-operator "qiskit_fermions.operators.FermionOperator").

  See [`fermion_operator()`](mappers-library-fermion-operator "qiskit_fermions.mappers.library.fermion_operator") for the type-agnostic helper function dispatching to the method below.

  <Admonition title="Caution" type="note">
    Despite the shared method name, this is *not* the same contract as [`ffsim.SupportsFermionOperator`](https://qiskit-community.github.io/ffsim/api/stubs/ffsim.SupportsFermionOperator.html#ffsim.SupportsFermionOperator "(in ffsim)"): this one returns a [`FermionOperator`](operators-fermion-operator "qiskit_fermions.operators.FermionOperator"), whereas ffsim’s returns an [`ffsim.FermionOperator`](https://qiskit-community.github.io/ffsim/api/stubs/ffsim.FermionOperator.html#ffsim.FermionOperator "(in ffsim)"). The two types are unrelated. Since [`ffsim.fermion_operator()`](https://qiskit-community.github.io/ffsim/api/stubs/ffsim.fermion_operator.html#ffsim.fermion_operator "(in ffsim)") dispatches purely on the method name, calling it on an operator of this package returns *this* package’s type rather than ffsim’s; use [`fermion_operator()`](mappers-library-fermion-operator "qiskit_fermions.mappers.library.fermion_operator") when that is what you mean.
  </Admonition>

  ```pycon
  >>> from qiskit_fermions.operators import MajoranaOperator
  >>> maj_op = MajoranaOperator.from_dict({(0, 1): 1})
  >>> fer_op = maj_op._fermion_operator_()
  >>> print(format(fer_op.normal_ordered().simplify()))
    0.000000e0 +1.000000e0j * ()
    0.000000e0 -2.000000e0j * (+0 -0)
  ```
