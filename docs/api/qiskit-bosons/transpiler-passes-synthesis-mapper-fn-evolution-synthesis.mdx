# MapperFnEvolutionSynthesis

<Class id="qiskit_bosons.transpiler.passes.synthesis.MapperFnEvolutionSynthesis" isDedicatedPage={true} signature="MapperFnEvolutionSynthesis(mapper_fn, product_formula=None)" modifiers="class">
  Bases: [`object`](https://docs.python.org/3/builtins/functions.html#object)

  A [`B2QSynthesisPlugin`](transpiler-passes-synthesis-b-2-q-synthesis-plugin "qiskit_bosons.transpiler.passes.synthesis.B2QSynthesisPlugin") for transpiling [`Evolution`](circuit-library-evolution "qiskit_bosons.circuit.library.Evolution") under a custom mapping.

  This plugin maps the bosonic Hamiltonian $H$ of the incoming [`Evolution`](circuit-library-evolution "qiskit_bosons.circuit.library.Evolution") gate to a qubit operator using [`mapper_fn`](#qiskit_bosons.transpiler.passes.synthesis.MapperFnEvolutionSynthesis.mapper_fn "qiskit_bosons.transpiler.passes.synthesis.MapperFnEvolutionSynthesis.mapper_fn") and emits a [`PauliEvolutionGate`](/docs/api/qiskit/qiskit.circuit.library.PauliEvolutionGate). It thereby preserves the $e^{-i t H}$ convention of the [`Evolution`](circuit-library-evolution "qiskit_bosons.circuit.library.Evolution") gate, with the same evolution time $t$.

  How that [`PauliEvolutionGate`](/docs/api/qiskit/qiskit.circuit.library.PauliEvolutionGate) is subsequently decomposed into basis gates is governed by the product formula passed as [`product_formula`](#qiskit_bosons.transpiler.passes.synthesis.MapperFnEvolutionSynthesis.product_formula "qiskit_bosons.transpiler.passes.synthesis.MapperFnEvolutionSynthesis.product_formula"). Leaving it at its default (`None`) defers to the [`PauliEvolutionGate`](/docs/api/qiskit/qiskit.circuit.library.PauliEvolutionGate)’s own default synthesis (a first-order [`LieTrotter`](/docs/api/qiskit/qiskit.synthesis.LieTrotter) decomposition with a single repetition). Supplying an explicit [`EvolutionSynthesis`](/docs/api/qiskit/qiskit.synthesis.EvolutionSynthesis) (for example a higher-order [`SuzukiTrotter`](/docs/api/qiskit/qiskit.synthesis.SuzukiTrotter) or one with several repetitions) selects a different Trotter-Suzuki product formula, trading circuit depth for a smaller Trotter error.

  <Admonition title="Note" type="note">
    The operator returned by [`mapper_fn`](#qiskit_bosons.transpiler.passes.synthesis.MapperFnEvolutionSynthesis.mapper_fn "qiskit_bosons.transpiler.passes.synthesis.MapperFnEvolutionSynthesis.mapper_fn") is passed on as-is, in particular **without** being simplified. A product formula synthesizes the Pauli terms in the order it receives them, so the term order that [`mapper_fn`](#qiskit_bosons.transpiler.passes.synthesis.MapperFnEvolutionSynthesis.mapper_fn "qiskit_bosons.transpiler.passes.synthesis.MapperFnEvolutionSynthesis.mapper_fn") produces is part of its output and is preserved here. A [`mapper_fn`](#qiskit_bosons.transpiler.passes.synthesis.MapperFnEvolutionSynthesis.mapper_fn "qiskit_bosons.transpiler.passes.synthesis.MapperFnEvolutionSynthesis.mapper_fn") that maps an operator group by group, for instance, emits the terms of each group together, which lets the terms of one group be scheduled in parallel where their supports are disjoint. See [`group_wise()`](transpiler-passes-synthesis-group-wise "qiskit_bosons.transpiler.passes.synthesis.group_wise"), which wraps any mapper to do exactly that.

    The occupation encodings write a ladder operator as `(X - iY)/2`, so the Pauli terms of a Hermitian group carry imaginary coefficients that cancel only once the terms are merged. [`occupation_encoding()`](mappers-library-occupation-encoding "qiskit_bosons.mappers.library.occupation_encoding") merges its result, using a tolerance relative to the largest coefficient so that the floating-point noise of the cancellation is removed too; a mapper of your own has to return an operator with real coefficients, since [`PauliEvolutionGate`](/docs/api/qiskit/qiskit.circuit.library.PauliEvolutionGate) rejects complex ones.
  </Admonition>

  <Admonition title="Caution" type="note">
    A consequence of preserving that order is that the synthesized circuit is only as reproducible as [`mapper_fn`](#qiskit_bosons.transpiler.passes.synthesis.MapperFnEvolutionSynthesis.mapper_fn "qiskit_bosons.transpiler.passes.synthesis.MapperFnEvolutionSynthesis.mapper_fn") is. The operators of the Rust core do **not** preserve the order in which their terms were added, so a mapper that walks an operator’s terms can emit them in a different order from one run to the next. The circuits that result are all equally valid (they approximate the same evolution of the same operator) but they need not be identical, and metrics such as depth or gate count can vary between them.

    Wrap the mapper in [`simplify()`](transpiler-passes-synthesis-simplify "qiskit_bosons.transpiler.passes.synthesis.simplify") to pin a canonical order where that matters:

    ```python
    MapperFnEvolutionSynthesis(simplify(mapper_fn))
    ```
  </Admonition>

  <Admonition title="Important" type="danger">
    [`product_formula`](#qiskit_bosons.transpiler.passes.synthesis.MapperFnEvolutionSynthesis.product_formula "qiskit_bosons.transpiler.passes.synthesis.MapperFnEvolutionSynthesis.product_formula") only subdivides the terms **within** the operator of a single [`Evolution`](circuit-library-evolution "qiskit_bosons.circuit.library.Evolution") gate. It cannot interleave *separate* gates, so when a grouped operator has already been decomposed into one [`Evolution`](circuit-library-evolution "qiskit_bosons.circuit.library.Evolution") per group (see [Group operator terms: use the operator structure](/docs/addons/qiskit-bosons/guides/grouping#grouping-explanation)), raising its repetition count does **not** reduce the outer Trotter error between the groups – which do not generally commute. The result stays a single outer Trotter step, and its error does not vanish as the repetition count grows.

    To converge the grouped evolution, repeat the whole thing: append `steps` [`Evolution`](circuit-library-evolution "qiskit_bosons.circuit.library.Evolution") gates at `time / steps` each. This is the flip side of grouping being decided upstream – the partition survives into the circuit, and so does responsibility for stepping it.
  </Admonition>

  Initializing this transpiler pass plugin can be done with the arguments listed below.

  **Parameters**

  *   **mapper\_fn** (*MapperFunction*) – the boson-to-qubit operator mapping function.
  *   **product\_formula** (*EvolutionSynthesis | None*) – the product formula with which to synthesize the emitted [`PauliEvolutionGate`](/docs/api/qiskit/qiskit.circuit.library.PauliEvolutionGate). If `None` (the default), the gate’s own default synthesis is used (a first-order [`LieTrotter`](/docs/api/qiskit/qiskit.synthesis.LieTrotter) decomposition with a single repetition).

  ### mapper\_fn

  <Attribute id="qiskit_bosons.transpiler.passes.synthesis.MapperFnEvolutionSynthesis.mapper_fn">
    Type: `MapperFunction`

    The boson-to-qubit operator mapping function.

    The two input arguments should be the following:

    1.  the operator to be mapped.
    2.  the number of qubits that the resulting operator should be defined on.

    <Admonition title="Note" type="note">
