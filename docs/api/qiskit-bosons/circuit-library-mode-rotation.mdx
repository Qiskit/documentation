# ModeRotation

<Class id="qiskit_bosons.circuit.library.ModeRotation" isDedicatedPage={true} signature="ModeRotation(rotation_unitary, *, synthesis=None)" modifiers="class">
  Bases: [`BosonicGate`](circuit-bosonic-gate "qiskit_bosons.circuit.bosonic_gate.BosonicGate")

  Implements a passive linear-optical mode transformation.

  Given an $M \times M$ unitary matrix $U$ (`rotation_unitary`), this gate implements the basis change that maps the creation operators as

$$
b^\dagger_i \mapsto \sum_j U_{ji} \, b^\dagger_j \, ,
$$

  equivalently the many-body unitary

$$
\exp\left(\sum_{ij} \log(U)_{ij} \, b^\dagger_i b_j\right) \, .
$$

  The number of bosonic modes the gate acts on is the dimension $M$ of `rotation_unitary`.

  **Action on the occupation sectors**

  Restricted to the *single-particle* sector, the gate is the $M \times M$ matrix $U$ itself. It acts on *every* occupation sector at once, however: the two-particle block is the symmetric square of $U$ (carrying the $\sqrt{2}$ factors), and so on up to the truncation.

  **Synthesis**

  Breaking this gate down in bosonic space (into a circuit of smaller [`Evolution`](circuit-library-evolution "qiskit_bosons.circuit.library.Evolution") gates) is what the [`synthesis`](circuit-bosonic-gate#synthesis "qiskit_bosons.circuit.BosonicGate.synthesis") attribute governs. It is `None` by default, which leaves the gate whole: there is no preferred decomposition, and a method such as [`BosonicClementsDecomposition`](circuit-library-synthesis-bosonic-clements-decomposition "qiskit_bosons.circuit.library.synthesis.BosonicClementsDecomposition") is chosen explicitly, either here or for a whole circuit with the [`B2BSynthesis`](transpiler-passes-b-2-b-synthesis "qiskit_bosons.transpiler.passes.B2BSynthesis") transpiler pass. The circuit it produces implements the same unitary as the gate (on the untruncated Fock space), and it is the definition of the gate.

  A gate that is left whole reaches the boson-to-qubit stage, which needs a plugin registered for `ModeRotation` to lower it. The library ships none, because the transpiler preset decomposes the gate in bosonic space first. A plugin that maps the generator of [`to_operator()`](#qiskit_bosons.circuit.library.ModeRotation.to_operator "qiskit_bosons.circuit.library.ModeRotation.to_operator") directly is a few lines long; see [Lower a rotation without decomposing it](/docs/addons/qiskit-bosons/guides/mode-rotation#mode-rotation-direct-explanation). The two-mode [`beamsplitter()`](#qiskit_bosons.circuit.library.ModeRotation.beamsplitter "qiskit_bosons.circuit.library.ModeRotation.beamsplitter") follows the convention of Clements et al.   <span id="id1" />[\[1\]](#id2)

  <Admonition title="Warning" type="caution">
    Because this gate mixes occupation sectors *within* a mode, a truncation that merely bounds the initial per-mode occupation is not sufficient. Acting on $\lvert 1, 1 \rangle$, a two-mode rotation populates $\lvert 2, 0 \rangle$, so a cutoff of `max_occupation=1` silently produces a wrong state. The cutoff must bound the **total** boson number reachable in any single mode. This matters most when the modes have different cutoffs: a rotation moves bosons between modes, so each mode that can receive them needs a cutoff that covers what it can receive, not only what it starts with.
  </Admonition>

  This gate is passive: it conserves the total boson number (it is generated by number-conserving $b^\dagger_i b_j$ terms). The active Gaussian operations – squeezing and displacement – do not conserve boson number and are not expressible as a `ModeRotation`.

  <span id="id2" />

  \[1] ([1](#id1),[2](#id3))

  W. R. Clements et al., Optimal design for universal multiport interferometers, Optica 3, 1460 (2016), [arXiv:1603.08788](https://arxiv.org/abs/1603.08788).

  Initializing an instance of this gate can be done with the arguments listed below.

  **Parameters**

  *   **rotation\_unitary** (*np.ndarray*) – the $M \times M$ unitary matrix $U$ defining the mode transformation via $b^\dagger_i \mapsto \sum_j U_{ji} b^\dagger_j$. It must be square and unitary; this is the caller’s responsibility and is not verified.
  *   **synthesis** ([*B2BSynthesisPlugin*](circuit-library-synthesis-b-2-b-synthesis-plugin "qiskit_bosons.circuit.library.synthesis.B2BSynthesisPlugin") *| None*) – the boson-to-boson synthesis method with which to decompose this gate, when it gets decomposed at all. If `None` (the default), the gate has no bosonic decomposition and [`decompose()`](circuit-bosonic-circuit#decompose "qiskit_bosons.circuit.BosonicCircuit.decompose") leaves it in place.

  <Function id="qiskit_bosons.circuit.library.ModeRotation.beamsplitter" signature="beamsplitter(theta, phi=0.0)" modifiers="classmethod">
    Constructs the two-mode beamsplitter.

    Following the Clements convention,     <span id="id3" />[\[1\]](#id2) the two-mode transfer matrix is

$$
T(\theta, \phi) = \begin{pmatrix}
e^{i\phi}\cos\theta & -\sin\theta \\
e^{i\phi}\sin\theta & \cos\theta
\end{pmatrix} \, ,
$$

    which together with the single-mode phase shifts generates any $U(M)$ when arranged in the Clements mesh.

    **Parameters**

    **Returns**

  ### to\_operator

  <Function id="qiskit_bosons.circuit.library.ModeRotation.to_operator" signature="to_operator(tol=1e-12)">
    Returns the Hermitian generator of this gate as a [`BosonOperator`](operators-boson-operator "qiskit_bosons.operators.BosonOperator").

    Builds $H = \sum_{ij} \mathrm{i} \log(U)_{ij} \, b^\dagger_i b_j$, the Hermitian operator for which $e^{-\mathrm{i} H}$ is this gate. That is exactly the form of an [`Evolution`](circuit-library-evolution "qiskit_bosons.circuit.library.Evolution") gate at unit time, which makes this the bridge from the gate’s matrix form to the operator algebra, and hence to any boson-to-qubit encoding.

    The matrix logarithm of a unitary is anti-Hermitian only up to round-off, so the result is built from the anti-Hermitian part of $\log(U)$ and is *exactly* Hermitian, as a [`PauliEvolutionGate`](/docs/api/qiskit/qiskit.circuit.library.PauliEvolutionGate) requires of the mapped operator.

    **Parameters**

    **tol** ([*float*](https://docs.python.org/3/builtins/functions.html#float)) – entries of $H$ with magnitude at or below this are dropped. `logm` of a sparse or block-diagonal unitary leaves round-off in nominally-zero entries; keeping them would bloat the operator with meaningless terms.

    **Returns**

    The Hermitian generator as a [`BosonOperator`](operators-boson-operator "qiskit_bosons.operators.BosonOperator").
  </Function>
