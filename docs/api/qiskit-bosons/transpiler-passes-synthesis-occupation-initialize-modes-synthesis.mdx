# OccupationInitializeModesSynthesis

<Class id="qiskit_bosons.transpiler.passes.synthesis.OccupationInitializeModesSynthesis" isDedicatedPage={true} signature="OccupationInitializeModesSynthesis(spec)" modifiers="class">
  Bases: [`object`](https://docs.python.org/3/builtins/functions.html#object)

  A [`B2QSynthesisPlugin`](transpiler-passes-synthesis-b-2-q-synthesis-plugin "qiskit_bosons.transpiler.passes.synthesis.B2QSynthesisPlugin") for transpiling [`InitializeModes`](circuit-library-initialize-modes "qiskit_bosons.circuit.library.InitializeModes").

  Prepares each mode’s Fock state by setting the qubits of the bit pattern that the chosen occupation encoding assigns to that mode’s occupation level. This is a plain layer of [`XGate`](/docs/api/qiskit/qiskit.circuit.library.XGate) on the qubits the pattern sets – no entangling gate is needed for a product Fock state.

  <Admonition title="Warning" type="caution">
    This plugin makes the following assumptions, none of which it verifies:

    *   **The qubits start in the all-zero state, and the gate is the first one acting on its modes.** The pattern is applied with `X` gates, so it *toggles* the qubits rather than setting them. A second [`InitializeModes`](circuit-library-initialize-modes "qiskit_bosons.circuit.library.InitializeModes") gate on the same modes undoes the first one or, depending on the encoding, leaves the register in a state that no level of the truncation represents.
    *   **All-zero is the vacuum only under the compact encodings.** Under both unary encodings the pattern of level 0 sets a qubit, so a mode that no [`InitializeModes`](circuit-library-initialize-modes "qiskit_bosons.circuit.library.InitializeModes") gate acts on starts outside the one-hot subspace. Place an [`InitializeModes`](circuit-library-initialize-modes "qiskit_bosons.circuit.library.InitializeModes") gate on every mode of such a circuit, with [`InitializeModes.vacuum()`](circuit-library-initialize-modes#vacuum "qiskit_bosons.circuit.library.InitializeModes.vacuum") for the empty ones.
    *   **The** [`LevelSpec`](mappers-level-spec "qiskit_bosons.mappers.LevelSpec") **is the one used by the layout and the mapper.** The layout derives the qubit register from its spec and the mapper maps the operators with its own; this plugin places the pattern at the offsets of the spec it is given. If they differ, the qubits are set without an error, but not the qubits that the rest of the pipeline reads as that occupation. The preset builds all three from one spec.
  </Admonition>

  <Admonition title="Note" type="note">
    This plugin needs to know the **encoding** and the **truncation**, because “which qubits represent occupation 2” is exactly what an encoding defines. They are given by a [`LevelSpec`](mappers-level-spec "qiskit_bosons.mappers.LevelSpec") passed to the constructor rather than being read off the gate: the gate is encoding-agnostic by design, and deferring this choice to transpile time is what lets one bosonic circuit be lowered under several encodings. Each mode is checked against, and placed at the qubit offset of, its own entry in the spec.
  </Admonition>

  Initializing this plugin can be done with the arguments listed below.

  **Parameters**

  **spec** ([*LevelSpec*](mappers-level-spec "qiskit_bosons.mappers.LevelSpec")) – the [`LevelSpec`](mappers-level-spec "qiskit_bosons.mappers.LevelSpec") with which the rest of the pipeline truncates and encodes its modes. It must be the same spec as the layout and the mapper use.
