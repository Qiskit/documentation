## 0.14.0

<span id="release-notes-0-14-0-new-features" />

### New Features

*   [`qiskit_addon_sqd.fermion.diagonalize_fermionic_hamiltonian()`](/docs/api/qiskit-addon-sqd/fermion#qiskit_addon_sqd.fermion.diagonalize_fermionic_hamiltonian "qiskit_addon_sqd.fermion.diagonalize_fermionic_hamiltonian") now accepts sampled bitstrings as a two-dimensional NumPy boolean array in addition to a Qiskit [`BitArray`](/docs/api/qiskit/qiskit.primitives.BitArray).

*   Adds a [guide](/docs/addons/qiskit-addon-sqd/guides/integrate-fulqrum) showing how to use [fulqrum](https://github.com/qiskit-community/fulqrum) as a subspace solver for fermionic systems. To install the optional dependency, use the `fulqrum` extra:

    ```python
    pip install 'qiskit-addon-sqd[fulqrum]'
    ```

*   Adds a [guide](/docs/addons/qiskit-addon-sqd/guides/integrate-sbd) showing how to use the [SBD eigensolver](https://github.com/Qiskit/sbd-eigensolver-python) as a subspace solver for fermionic systems. To install the optional dependency, use the `sbd` extra:

    ```python
    pip install 'qiskit-addon-sqd[sbd]'
    ```

*   Adds the [`qiskit_addon_sqd.trim`](/docs/api/qiskit-addon-sqd/trim#module-qiskit_addon_sqd.trim "qiskit_addon_sqd.trim") module, containing [`TrimPolicy`](/docs/api/qiskit-addon-sqd/trim#qiskit_addon_sqd.trim.TrimPolicy "qiskit_addon_sqd.trim.TrimPolicy"). This implements *trim SQD*, a schedule that treats the subsampled batches as candidates to be screened rather than as independent estimates: each batch is diagonalized and trimmed down to the CI strings carrying the largest weight, and the survivors of all the batches are merged and diagonalized together. The merged diagonalization is what the iteration reports, and its own trimmed strings seed the next one.

    An iteration therefore costs `num_batches + 1` diagonalizations rather than `num_batches`. Screening only selects among batches that differ, so [`TrimPolicy`](/docs/api/qiskit-addon-sqd/trim#qiskit_addon_sqd.trim.TrimPolicy "qiskit_addon_sqd.trim.TrimPolicy") draws them as a single pool of `samples_per_batch * num_batches` bitstrings divided among the batches, leaving no bitstring in more than one. That follows from what the schedule does and is not separately configurable.

*   Adds a [guide](/docs/addons/qiskit-addon-sqd/guides/trim-sqd) covering trim SQD, including how to bound the subspace that trimming produces and how to check whether the screening step is helping on a given system.

*   [`diagonalize_fermionic_hamiltonian()`](/docs/api/qiskit-addon-sqd/fermion#qiskit_addon_sqd.fermion.diagonalize_fermionic_hamiltonian "qiskit_addon_sqd.fermion.diagonalize_fermionic_hamiltonian") has a new `policy` argument, which selects the schedule each iteration follows: how the sampled configurations become subspaces, whether one round of diagonalizations leads to another, which result the iteration reports, and which CI strings seed the next one. Trim SQD is chosen by passing a [`TrimPolicy`](/docs/api/qiskit-addon-sqd/trim#qiskit_addon_sqd.trim.TrimPolicy "qiskit_addon_sqd.trim.TrimPolicy"). The argument defaults to [`StandardPolicy`](/docs/api/qiskit-addon-sqd/fermion#qiskit_addon_sqd.fermion.StandardPolicy "qiskit_addon_sqd.fermion.StandardPolicy"), the behavior this function has always had, so omitting it changes nothing.

    A policy is described by the [`SubspacePolicy`](/docs/api/qiskit-addon-sqd/fermion#qiskit_addon_sqd.fermion.SubspacePolicy "qiskit_addon_sqd.fermion.SubspacePolicy") protocol and receives its inputs as a [`SubspaceRequest`](/docs/api/qiskit-addon-sqd/fermion#qiskit_addon_sqd.fermion.SubspaceRequest "qiskit_addon_sqd.fermion.SubspaceRequest"). It returns the subspaces and the loop calls `sci_solver` with them, so a schedule and an eigensolver are chosen independently and any combination works.

    A policy chooses *which strings* a subspace holds. The constraints on the *shape* of a subspace remain the caller’s: the configurations requested through `include_configurations` go into every subspace, spin symmetrization is enforced where it was asked for, and each spin sector is truncated to `max_dim`.

*   An `sci_solver` may now report the configurations it wants carried into the next iteration, and may skip returning the eigenvector altogether. This is what lets trim SQD scale: an eigensolver that ranks and trims its own subspace already knows which configurations survive, and the eigenvector it would otherwise have to hand back is of size `len(strings_a) * len(strings_b)` – the one quantity a large distributed calculation cannot afford to move between processes.

    Two additions to [`SCIResult`](/docs/api/qiskit-addon-sqd/fermion#qiskit_addon_sqd.fermion.SCIResult "qiskit_addon_sqd.fermion.SCIResult") provide this. The new optional field [`carryover`](/docs/api/qiskit-addon-sqd/fermion#qiskit_addon_sqd.fermion.SCIResult.carryover "qiskit_addon_sqd.fermion.SCIResult.carryover") holds a pair `(strings_a, strings_b)` of CI strings; when a solver sets it, those strings are used in place of the ones that would otherwise be selected from the eigenvector amplitudes using `carryover_threshold`. And [`sci_state`](/docs/api/qiskit-addon-sqd/fermion#qiskit_addon_sqd.fermion.SCIResult.sci_state "qiskit_addon_sqd.fermion.SCIResult.sci_state") may now be `None`, so that a solver which never materializes the eigenvector does not have to fabricate one. Such a solver must set [`carryover`](/docs/api/qiskit-addon-sqd/fermion#qiskit_addon_sqd.fermion.SCIResult.carryover "qiskit_addon_sqd.fermion.SCIResult.carryover"), since there would otherwise be nothing to build the next subspace from; a result with neither now raises `ValueError`.

    The solvers built into this package always return an eigenvector, so nothing changes for callers using them.

*   Adds [`partition_subsample()`](/docs/api/qiskit-addon-sqd/subsampling#qiskit_addon_sqd.subsampling.partition_subsample "qiskit_addon_sqd.subsampling.partition_subsample"), which draws a pool of bitstrings and divides it among the batches so that they are disjoint. This is what [`TrimPolicy`](/docs/api/qiskit-addon-sqd/trim#qiskit_addon_sqd.trim.TrimPolicy "qiskit_addon_sqd.trim.TrimPolicy") uses, exposed for callers writing a policy of their own.

*   Adds [`batch_to_ci_strings()`](/docs/api/qiskit-addon-sqd/fermion#qiskit_addon_sqd.fermion.batch_to_ci_strings "qiskit_addon_sqd.fermion.batch_to_ci_strings"), which converts a batch of bitstrings into a pair of per-spin CI string arrays ranked by the number of times each string was sampled. This is the step that turns subsampled bitstrings into a subspace, exposed so that a policy does not have to reimplement it.

<span id="release-notes-0-14-0-upgrade-notes" />

### Upgrade Notes

*   NumPy 2.0 and SciPy 1.14.1 are now the minimum required versions. Support for NumPy 1.x has been dropped, following Qiskit’s adoption of [SPEC 0](https://scientific-python.org/specs/spec-0000/).

*   The minimum version of Qiskit is now 2.0.

*   Code that reads [`sci_state`](/docs/api/qiskit-addon-sqd/fermion#qiskit_addon_sqd.fermion.SCIResult.sci_state "qiskit_addon_sqd.fermion.SCIResult.sci_state") from a result produced by a custom `sci_solver` should be prepared for `None`, as the field is now optional. Results from the solvers built into this package always populate it, so callers using the default solver are unaffected.

*   `carryover_threshold` is now a setting of the default policy, which is what chooses the carryover by thresholding amplitudes. It remains an argument of [`diagonalize_fermionic_hamiltonian()`](/docs/api/qiskit-addon-sqd/fermion#qiskit_addon_sqd.fermion.diagonalize_fermionic_hamiltonian "qiskit_addon_sqd.fermion.diagonalize_fermionic_hamiltonian") with the same meaning and the same default, but passing it together with an explicit `policy` raises `ValueError` rather than being silently ignored, since another policy chooses the carryover in its own way. Pass the threshold to [`StandardPolicy`](/docs/api/qiskit-addon-sqd/fermion#qiskit_addon_sqd.fermion.StandardPolicy "qiskit_addon_sqd.fermion.StandardPolicy") when constructing one explicitly.

## 0.13.0

<span id="release-notes-0-13-0-new-features" />

<span id="id5" />

### New Features

*   Added support for Python 3.13 and Python 3.14. No code changes were necessary, so older releases are expected to work on Python 3.13 and 3.14 too.

*   [`qiskit_addon_sqd.fermion.diagonalize_fermionic_hamiltonian()`](/docs/api/qiskit-addon-sqd/fermion#qiskit_addon_sqd.fermion.diagonalize_fermionic_hamiltonian "qiskit_addon_sqd.fermion.diagonalize_fermionic_hamiltonian") can now be called collectively from all processes of a multi-process (SPMD) execution, for example under MPI. When invoked this way, the `sci_solver` step runs on every process, so a custom, distributed `sci_solver` can spread each diagonalization across the available processes; the rest of the configuration-recovery loop runs on the control process alone, and the return value is the same on every process. Single-process behavior is unchanged. See [this guide](/docs/addons/qiskit-addon-sqd/guides/hpc-acceleration) for details on the package’s support for multi-process and multi-threaded acceleration.

### Deprecation Notes

*   The `qiskit_addon_sqd.fermion.bitstring_matrix_to_sorted_addresses` function has been deprecated in favor of [`qiskit_addon_sqd.fermion.bitstring_matrix_to_ci_strs()`](/docs/api/qiskit-addon-sqd/fermion#qiskit_addon_sqd.fermion.bitstring_matrix_to_ci_strs "qiskit_addon_sqd.fermion.bitstring_matrix_to_ci_strs"). These two functions behave the same with one key exception – `qiskit_addon_sqd.fermion.bitstring_matrix_to_sorted_addresses` returns the configurations as `tuple(spin_dn, spin_up)`; whereas, [`qiskit_addon_sqd.fermion.bitstring_matrix_to_ci_strs()`](/docs/api/qiskit-addon-sqd/fermion#qiskit_addon_sqd.fermion.bitstring_matrix_to_ci_strs "qiskit_addon_sqd.fermion.bitstring_matrix_to_ci_strs") returns the configurations as `tuple(spin_up, spin_dn)`.

    To migrate

    ```python
    from qiskit_addon_sqd.fermion import (
        bitstring_matrix_to_sorted_addresses,
        bitstring_matrix_to_ci_strs,
    )

    # DEPRECATED CODE
    bs_matrix = ...
    addr_dn, addr_up = bitstring_matrix_to_sorted_addresses(bs_matrix, open_shell=True)

    ### SHOULD BECOME ###

    # NEW CODE
    bs_matrix = ...
    ci_strs_up, ci_strs_dn = bitstring_matrix_to_ci_strs(bs_matrix, open_shell=True)
    ```

*   The `addresses` argument to [`qiskit_addon_sqd.fermion.solve_fermion()`](/docs/api/qiskit-addon-sqd/fermion#qiskit_addon_sqd.fermion.solve_fermion "qiskit_addon_sqd.fermion.solve_fermion") and [`qiskit_addon_sqd.fermion.optimize_orbitals()`](/docs/api/qiskit-addon-sqd/fermion#qiskit_addon_sqd.fermion.optimize_orbitals "qiskit_addon_sqd.fermion.optimize_orbitals") has been deprecated in favor of `bitstring_matrix`. Users are no longer required to convert their configurations to integers; instead, they should now pass in the bitstring matrix specifying the subspace onto which to project and diagonalize the Hamiltonian. The conversion to the integer representation of determinants will be done internally.
