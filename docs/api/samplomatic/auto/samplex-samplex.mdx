# Samplex

<Class id="samplomatic.samplex.Samplex" isDedicatedPage={true} github="https://github.com/Qiskit/samplomatic/tree/main/samplomatic/samplex/samplex.py#L53-L532" signature="samplomatic.samplex.Samplex" modifiers="class">
  Bases: [`object`](https://docs.python.org/3/builtins/functions.html#object)

  Represents a probability distribution over circuit parameters and other fields.

  [`Samplex`](#samplomatic.samplex.Samplex "samplomatic.samplex.Samplex") is the core type of the samplomatic library. It is a portmanteau of “sampling complex”.

  In abstract terms, a samplex represents a parametric probability distribution over the parameters of some template circuit, as well as other array-valued fields to use in post-processing data collected from executing the bound template circuit. In practical terms, it implements a [`sample()`](#samplomatic.samplex.Samplex.sample "samplomatic.samplex.Samplex.sample") method that draws from this distribution to produce a collection of arrays that include at least an array of (random) angles valid for the template circuit. For example, a samplex instance might implement Pauli twirling on all the layers of some base circuit including final measurements, so that the angles returned by sampling from it correspond to Pauli gates composed with whatever single-qubit gates exist in the base circuit, along with bool arrays that describe how to invert those measurement results flipped by measurement twirling. However, its semantics are not limited to this, and its structure is highly extensible: new group types, new distributions, new virtual gate propagation techniques can be added to the library.

  Internally, a samplex uses a directed acyclic graph (DAG) representation that describes the sampling process procedurally. Each node of the graph interacts with a collection of [`VirtualRegister`](virtual-registers-virtual-register "samplomatic.virtual_registers.VirtualRegister")s, and connections between nodes denote register dependency: if $A \rightarrow B$, then $B$ requires $A$ to have acted on the registers before it is allowed to act. This implies that the flow of the graph is not temporal with respect to execution like the DAG of a quantum circuit, but instead flows from nodes responsible for generating randomizations to nodes responsible for rendering the processed randomizations as outputs. There are three types of nodes:

  *   [`SamplingNode`](samplex-nodes-sampling-node "samplomatic.samplex.nodes.SamplingNode")s are responsible for instantiating new registers from inputs,
  *   [`EvaluationNode`](samplex-nodes-evaluation-node "samplomatic.samplex.nodes.EvaluationNode")s are responsible for transforming, combining, and removing registers,
  *   [`CollectionNode`](samplex-nodes-collection-node "samplomatic.samplex.nodes.CollectionNode")s are responsible reading registers and writing to output values of [`sample()`](#samplomatic.samplex.Samplex.sample "samplomatic.samplex.Samplex.sample").

  Samplexes are typically generated by passing a base circuit with annotated box instructions to the [`build()`](build "samplomatic.build") function. Generating one manually is possible, though tedious, and the user is then also responsible for constructing a compatible parametric quantum circuit to use as the template circuit. The following example shows a simple circuit built into a samplex and template pair using the [`build()`](build "samplomatic.build") function, and plots the resulting DAG of the samplex. The three different types of nodes described above are denoted by different shapes.

  ```python
  >>> from samplomatic import build, Twirl
  >>> from qiskit import QuantumCircuit
  >>>
  >>> circuit = QuantumCircuit(2)
  >>> with circuit.box([Twirl()]):
  ...    circuit.cz(0, 1)
  >>> with circuit.box([Twirl()]):
  ...     circuit.measure_all()
  >>>
  >>> template, samplex = build(circuit)
  >>> samplex.draw()
  ```

  Although the DAG is the main component of the data model this object, other information is also stored:

  *   Samplexes themselves can be parametric (see [`parameters`](#samplomatic.samplex.Samplex.parameters "samplomatic.samplex.Samplex.parameters")) and evaluate parameter expressions, all of which is stored by the samplex. For example, when constructed via [`build()`](build "samplomatic.build"), a samplex will accept values for all of the parameters accepted by the base circuit.
  *   Input and output specifications that describe exactly what values are expected as input at [`sample()`](#samplomatic.samplex.Samplex.sample "samplomatic.samplex.Samplex.sample") time, and what values will be returned, see [`inputs()`](#samplomatic.samplex.Samplex.inputs "samplomatic.samplex.Samplex.inputs") and [`outputs()`](#samplomatic.samplex.Samplex.outputs "samplomatic.samplex.Samplex.outputs").
  *   Noise model requirements that specify what types of noise models are compatible with the sampling needs of a samplex.

  ### param\_table

  <Attribute id="samplomatic.samplex.Samplex.param_table">
    The [`ParameterExpressionTable`](samplex-parameter-expression-table "samplomatic.samplex.ParameterExpressionTable") owning this samplex’s parameter expressions.

    Parametric nodes added to the samplex reference entries of this table by index, and [`sample()`](#samplomatic.samplex.Samplex.sample "samplomatic.samplex.Samplex.sample") evaluates the table at sampling time. Combined with [`passthrough_params`](#samplomatic.samplex.Samplex.passthrough_params "samplomatic.samplex.Samplex.passthrough_params"), callers can evaluate just the deterministic subset of template parameters (e.g., [`RZZGate`](/docs/api/qiskit/qiskit.circuit.library.RZZGate) angles) without invoking [`sample()`](#samplomatic.samplex.Samplex.sample "samplomatic.samplex.Samplex.sample"). See also [`parameters`](#samplomatic.samplex.Samplex.parameters "samplomatic.samplex.Samplex.parameters") and [`append_parameter_expression()`](#samplomatic.samplex.Samplex.append_parameter_expression "samplomatic.samplex.Samplex.append_parameter_expression").
  </Attribute>

  ### passthrough\_params

  <Attribute id="samplomatic.samplex.Samplex.passthrough_params">
    The index mapping that drives passthrough template parameters.

    Returns a pair of equal-length, positionally aligned integer arrays `(template_idxs, expression_idxs)`: the value at template parameter index `template_idxs[i]` is set during [`sample()`](#samplomatic.samplex.Samplex.sample "samplomatic.samplex.Samplex.sample") from the value of the [`param_table`](#samplomatic.samplex.Samplex.param_table "samplomatic.samplex.Samplex.param_table") expression at index `expression_idxs[i]` (see [`set_passthrough_params()`](#samplomatic.samplex.Samplex.set_passthrough_params "samplomatic.samplex.Samplex.set_passthrough_params")).

    Both arrays are empty if no passthrough parameters are registered. The returned arrays are independent copies of the internal state.
  </Attribute>

  ### sample

  <Function id="samplomatic.samplex.Samplex.sample" github="https://github.com/Qiskit/samplomatic/tree/main/samplomatic/samplex/samplex.py#L343-L480" signature="sample(samplex_input: Mapping[str, Any] | None = None, num_randomizations: int = 1, rng: int | SeedSequence | Generator | None = None, keep_registers: bool = False, max_workers: int | None = None) → SamplexOutput">
    Sample.

    The following example builds a simple circuit with two parameters into a samplex to demonstrate calling this method. In particular, note that required inputs to the samplex nodes, which includes both type and array shape information, are listed by [`inputs()`](#samplomatic.samplex.Samplex.inputs "samplomatic.samplex.Samplex.inputs"), and need to be bound with values.

    ```python
    >>> from samplomatic import build, Twirl
    >>> from qiskit.circuit import QuantumCircuit, Parameter
    >>>
    >>> # quickly make a circuit and build it to construct an example simplex
    >>> circuit = QuantumCircuit(2)
    >>> with circuit.box([Twirl()]):
    ...     circuit.rx(Parameter("a"), 0)
    ...     circuit.rx(Parameter("b"), 0)
    ...     circuit.cz(0, 1)
    >>> with circuit.box([Twirl()]):
    ...     circuit.measure_all()
    >>>
    >>> template, samplex = build(circuit)
    >>>
    >>> # query the samplex for the expected inputs at sample time, and note that we
    >>> # are required to pass a length-2 vector of floats for 'a' and 'b' (alphabetical)
    >>> print(inputs := samplex.inputs())
    TensorInterface(<
        - 'parameter_values' <float64[2]>: Input parameter values to use during sampling.
    >)
    ```

    ```python
    >>> # after binding required values, we can sample 123 randomizations
    >>> samplex.sample(
    ...     inputs.bind(parameter_values=[0.1, 0.2]),
    ...     num_randomizations=123,
    ... )
    SamplexOutput({'measurement_flips.meas': ..., 'parameter_values': ...})
    ```

    ```python
    >>> # alternatively, we can provide any mapping object directly to specify inputs
    >>> samplex.sample(
    ...     {"parameter_values": [0.1, 0.2]},
    ...     num_randomizations=123,
    ... )
    SamplexOutput({'measurement_flips.meas': ..., 'parameter_values': ...})
    ```

    **Parameters**

    *   **samplex\_input** – A mapping from input names to input values, as described by [`inputs()`](#samplomatic.samplex.Samplex.inputs "samplomatic.samplex.Samplex.inputs") (see also the [Samplex inputs and outputs](/docs/guides/samplex-io) guide), or `None` if no input is required. Names that contain a period can use nested dictionary expansion. Note that [`TensorInterface`](tensor-interface-tensor-interface "samplomatic.tensor_interface.TensorInterface") is a mapping object and is therefore a valid input argument when fully bound.
    *   **num\_randomizations** – The number of randomizations to sample.
    *   **keep\_registers** – Whether to keep the virtual registers used during sampling and include them in the output under the metadata key `"registers"`.
    *   **rng** – An integer for seeding a randomness generator, a generator itself, or `None` to use the default generator owned by the module.
    *   **max\_workers** – The maximum number of threads that can be used to execute the parallel execution of sampling, evaluation, and collection nodes.
  </Function>
