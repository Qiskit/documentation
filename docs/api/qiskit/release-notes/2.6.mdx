# Qiskit SDK 2.6 release notes

<span id="relnotes-2-6-0" />

<span id="id1" />

## 2.6.0

<span id="relnotes-2-6-0-prelude" />

### Prelude

Qiskit v2.6.0 is a new feature release of the Qiskit SDK.

This release introduces important new functionality into the Qiskit SDK, including the following:

*   **A Multi-IR Pass Manager in C and Python:** Added a new pass manager framework which can use different Intermediate Representations (IRs) as input and outputs. This framework is exposed to Python via the [`LoweringPassManager`](/docs/api/qiskit/passmanager#qiskit.passmanager.LoweringPassManager "qiskit.passmanager.LoweringPassManager") class and to the C API too. Refer to the C API [Pass-manager infrastructure](/docs/api/qiskit-c/pass-manager#capi-pass-manager) documentation for more details on using this new pass manager from C.

*   **Custom Operations in C:** Users are now able to create custom [`Operation`](/docs/api/qiskit/qiskit.circuit.Operation "qiskit.circuit.Operation") types using the C API. See the [QkCustomOp](/docs/api/qiskit-c/qk-operation#capi-operations) documentation for more details.

*   **QPY 18 and C API:**

    *   QPY serialization and de-serialization is now available via the C API. Users are now able to use QPY for roundtrip serialization from C as well as inter-operate with Python workflows. Please note that loading QPY from C is only supported for payloads using QPY v13 and onwards. Refer to [the QPY C API documentation](/docs/api/qiskit-c/qk-qpy#capi-qpy) for more details.
    *   QPY v18 which introduces a new format version and produces payloads with smaller footprints. Refer to [the QPY Version 18 documentation](/docs/api/qiskit/qpy#qpy-version-18) for more details on the changes in the new format revision.

<span id="relnotes-2-6-0-c-api-features" />

### C API Features

*   Custom operations can now be defined via the C API using `QkCustomOp`. Any implementors should refer to the documentation defined in [QkCustomOp](/docs/api/qiskit-c/qk-operation#capi-operations) for further information.

*   Add [`qk_circuit_custom_operation()`](/docs/api/qiskit-c/qk-circuit#qk_circuit_custom_operation "qk_circuit_custom_operation") and [`qk_dag_apply_custom_operation()`](/docs/api/qiskit-c/qk-dag#qk_dag_apply_custom_operation "qk_dag_apply_custom_operation") to add custom operations defined in C to a circuit.

*   Added ability to add [`Delay`](/docs/api/qiskit/circuit#qiskit.circuit.Delay "qiskit.circuit.Delay") in terms of `Dt` to a `QkCircuit` (via [`qk_circuit_delay_dt()`](/docs/api/qiskit-c/qk-circuit#qk_circuit_delay_dt "qk_circuit_delay_dt")).

*   Add [`qk_circuit_delay_unit()`](/docs/api/qiskit-c/qk-circuit#qk_circuit_delay_unit "qk_circuit_delay_unit") to retrieve the unit type of a [`Delay`](/docs/api/qiskit/circuit#qiskit.circuit.Delay "qiskit.circuit.Delay") instruction in the C API.

*   Add [`qk_param_kind()`](/docs/api/qiskit-c/qk-param#qk_param_kind "qk_param_kind") to obtain an enumeration ([`QkParamKind`](/docs/api/qiskit-c/qk-param#QkParamKind "QkParamKind")) describing the kind of any `QkParam` instance before using functions such as [`qk_param_as_real()`](/docs/api/qiskit-c/qk-param#qk_param_as_real "qk_param_as_real") or [`qk_param_as_int()`](/docs/api/qiskit-c/qk-param#qk_param_as_int "qk_param_as_int") to obtain its bound value.

*   Add [`qk_param_as_int()`](/docs/api/qiskit-c/qk-param#qk_param_as_int "qk_param_as_int") to obtain the integer value of a parameter that can only be represented by an integer.

*   [`qk_circuit_barrier()`](/docs/api/qiskit-c/qk-circuit#qk_circuit_barrier "qk_circuit_barrier") can now accept a null pointer as the `qubits` argument, in which case `num_qubits` is ignored, and the barrier is applied to all qubits.

*   Two new functions, [`qk_circuit_view_instruction()`](/docs/api/qiskit-c/qk-circuit#qk_circuit_view_instruction "qk_circuit_view_instruction") and [`qk_dag_view_instruction()`](/docs/api/qiskit-c/qk-dag#qk_dag_view_instruction "qk_dag_view_instruction"), were added as mirrors to [`qk_circuit_get_instruction()`](/docs/api/qiskit-c/qk-circuit#qk_circuit_get_instruction "qk_circuit_get_instruction") and [`qk_dag_get_instruction()`](/docs/api/qiskit-c/qk-dag#qk_dag_get_instruction "qk_dag_get_instruction"), respectively, writing out a new [`QkCircuitInstructionView`](/docs/api/qiskit-c/qk-circuit#QkCircuitInstructionView "QkCircuitInstructionView") object.

    These `view` functions produce direct views into the internal data without any allocations, which is more performant, but requires some special handling to use the non-idiomatic data formats from C; see the documentation of [`QkCircuitInstructionView`](/docs/api/qiskit-c/qk-circuit#QkCircuitInstructionView "QkCircuitInstructionView").

*   Added [`qk_param_stride()`](/docs/api/qiskit-c/qk-param#qk_param_stride "qk_param_stride"), which returns the runtime size in bytes needed to offset `QkParam *` pointers that point to contiguous arrays.

*   The C API now has a pass manager framework for writing and executing compiler passes. The new `QkPassManager` manages the execution; it can be populated with [`QkPass`](/docs/api/qiskit-c/pass-manager#QkPass "QkPass") objects via [`qk_passmanager_push_pass()`](/docs/api/qiskit-c/pass-manager#qk_passmanager_push_pass "qk_passmanager_push_pass") and be executed using [`qk_passmanager_run_simple()`](/docs/api/qiskit-c/pass-manager#qk_passmanager_run_simple "qk_passmanager_run_simple"). The pass manager and passes can report errors through [`QkCompilationError`](/docs/api/qiskit-c/pass-manager#QkCompilationError "QkCompilationError").

    Passes are defined through a vtable, [`QkPassVtable`](/docs/api/qiskit-c/pass-manager#QkPassVtable "QkPassVtable"), and declare their input and output IR with an [`QkIrHandle`](/docs/api/qiskit-c/pass-manager#QkIrHandle "QkIrHandle"), which can describe either a dynamically defined C IR or a built-in Qiskit IR. The pass manager uses these handles to verify the pipeline, enabling type-checked cross-language compiler pipelines.

    The functionality included in this release is limited and we expect to expand the C pass manager framework in a backward-compatible manner, for example, with additional execution modes of the pass manager, callbacks, and pass context handling.

*   Added C API functions to construct n-local circuits:

    > *   [`qk_circuit_library_n_local()`](/docs/api/qiskit-c/qk-circuit-library#qk_circuit_library_n_local "qk_circuit_library_n_local"): Constructs an n-local variational circuit.
    > *   [`qk_circuit_library_n_local_settings_default()`](/docs/api/qiskit-c/qk-circuit-library#qk_circuit_library_n_local_settings_default "qk_circuit_library_n_local_settings_default"): Generates default options for [`qk_circuit_library_n_local()`](/docs/api/qiskit-c/qk-circuit-library#qk_circuit_library_n_local "qk_circuit_library_n_local").

    The following helper structs were also added:

    > *   [`QkNLocalSettings`](/docs/api/qiskit-c/qk-circuit-library#QkNLocalSettings "QkNLocalSettings"): Holds settings needed to build the n-local circuit.
    > *   [`QkEntanglementStrategy`](/docs/api/qiskit-c/qk-circuit-library#QkEntanglementStrategy "QkEntanglementStrategy"): Enum representing all the strategies that can be used for the circuit entanglement blocks.

*   Added [`qk_obs_with_capacity()`](/docs/api/qiskit-c/qk-obs#qk_obs_with_capacity "qk_obs_with_capacity") for constructing empty `QkObs` instances with a pre-allocated capacity for terms.

*   Added QPY serialization and deserialization to the C API. Multiple `QkCircuit` objects can now be serialized into a single QPY stream in the latest QPY version, either to a buffer with [`qk_qpy_dump_buffer()`](/docs/api/qiskit-c/qk-qpy#qk_qpy_dump_buffer "qk_qpy_dump_buffer") or saved to a file with [`qk_qpy_dump_file()`](/docs/api/qiskit-c/qk-qpy#qk_qpy_dump_file "qk_qpy_dump_file"). Both functions have an alternative `*_with_version` variant that allows specifying the QPY version used for serialization.

    These dump functions operate on native circuits without interacting with Python. If you’re using the C API in a Python extension you should use the Python functions: [`qpy.dump()`](/docs/api/qiskit/qpy#qiskit.qpy.dump "qiskit.qpy.dump") and [`qpy.load()`](/docs/api/qiskit/qpy#qiskit.qpy.load "qiskit.qpy.load") as the C API functions will return an error if Python is required to create or load a QPY payload from the circuit.

    All circuits in a QPY stream can be deserialized from a buffer or file with [`qk_qpy_load_buffer()`](/docs/api/qiskit-c/qk-qpy#qk_qpy_load_buffer "qk_qpy_load_buffer") and [`qk_qpy_load_file()`](/docs/api/qiskit-c/qk-qpy#qk_qpy_load_file "qk_qpy_load_file") (the version is handled automatically; no need for variants).

    To free the buffer returned by [`qk_qpy_dump_buffer()`](/docs/api/qiskit-c/qk-qpy#qk_qpy_dump_buffer "qk_qpy_dump_buffer") and [`qk_qpy_dump_buffer_with_version()`](/docs/api/qiskit-c/qk-qpy#qk_qpy_dump_buffer_with_version "qk_qpy_dump_buffer_with_version"), call [`qk_qpy_free_buffer()`](/docs/api/qiskit-c/qk-qpy#qk_qpy_free_buffer "qk_qpy_free_buffer"). Circuit arrays returned by [`qk_qpy_load_buffer()`](/docs/api/qiskit-c/qk-qpy#qk_qpy_load_buffer "qk_qpy_load_buffer") and [`qk_qpy_load_file()`](/docs/api/qiskit-c/qk-qpy#qk_qpy_load_file "qk_qpy_load_file") must be released with `qk_qpy_free_circuits()`.

    Each function that can fail accepts a nullable output pointer for a diagnostic error string. When populated, the string contains details from the underlying QPY error and must be released with [`qk_str_free()`](/docs/api/qiskit-c/qk-obs#qk_str_free "qk_str_free").

    Also added [`qk_qpy_read_min_version()`](/docs/api/qiskit-c/qk-qpy#qk_qpy_read_min_version "qk_qpy_read_min_version") and [`qk_qpy_write_min_version()`](/docs/api/qiskit-c/qk-qpy#qk_qpy_write_min_version "qk_qpy_write_min_version"), which return the oldest QPY format versions the loaded library can read and write, respectively.

    The new functions are:

    *   [`qk_qpy_dump_file()`](/docs/api/qiskit-c/qk-qpy#qk_qpy_dump_file "qk_qpy_dump_file")
    *   [`qk_qpy_dump_file_with_version()`](/docs/api/qiskit-c/qk-qpy#qk_qpy_dump_file_with_version "qk_qpy_dump_file_with_version")
    *   [`qk_qpy_load_file()`](/docs/api/qiskit-c/qk-qpy#qk_qpy_load_file "qk_qpy_load_file")
    *   [`qk_qpy_dump_buffer()`](/docs/api/qiskit-c/qk-qpy#qk_qpy_dump_buffer "qk_qpy_dump_buffer")
    *   [`qk_qpy_dump_buffer_with_version()`](/docs/api/qiskit-c/qk-qpy#qk_qpy_dump_buffer_with_version "qk_qpy_dump_buffer_with_version")
    *   [`qk_qpy_load_buffer()`](/docs/api/qiskit-c/qk-qpy#qk_qpy_load_buffer "qk_qpy_load_buffer")
    *   [`qk_qpy_free_buffer()`](/docs/api/qiskit-c/qk-qpy#qk_qpy_free_buffer "qk_qpy_free_buffer")
    *   `qk_qpy_free_circuits()`
    *   [`qk_qpy_read_min_version()`](/docs/api/qiskit-c/qk-qpy#qk_qpy_read_min_version "qk_qpy_read_min_version")
    *   [`qk_qpy_write_min_version()`](/docs/api/qiskit-c/qk-qpy#qk_qpy_write_min_version "qk_qpy_write_min_version")

*   The C circuit drawer now renders [`Barrier`](/docs/api/qiskit/circuit#qiskit.circuit.Barrier "qiskit.circuit.Barrier") labels, matching the behavior of the Python text drawer. The label is drawn above the top-most wire of the barrier and is truncated, with `"..."` appended, when it is longer than the configured number of characters (16 by default).

*   [`QkCircuitDrawerConfig`](/docs/api/qiskit-c/qk-circuit#QkCircuitDrawerConfig "QkCircuitDrawerConfig") has a new `barrier_label_len` field, which controls the number of characters to display for barrier labels. Longer labels are truncated at that length and `"..."` is appended. Setting the field to `0` applies the default truncation length of 16 characters, so existing initializers that omit the field keep the default behavior.

### Circuits Features

*   The type that backs [`QuantumCircuit._data`](/docs/api/qiskit/qiskit.circuit.QuantumCircuit#_data "qiskit.circuit.QuantumCircuit._data") is now nameable as [`qiskit.circuit.CircuitData`](/docs/api/qiskit/circuit#qiskit.circuit.CircuitData "qiskit.circuit.CircuitData"). All methods and attributes on the object are still private, regardless of their naming convention.

*   A new public constructor, [`QuantumCircuit.from_circuit_data()`](/docs/api/qiskit/qiskit.circuit.QuantumCircuit#from_circuit_data "qiskit.circuit.QuantumCircuit.from_circuit_data"), allows reconstruction of a full circuit from the [`_data`](/docs/api/qiskit/qiskit.circuit.QuantumCircuit#_data "qiskit.circuit.QuantumCircuit._data") attribute.

*   Conversions between [`DAGCircuit`](/docs/api/qiskit/qiskit.dagcircuit.DAGCircuit "qiskit.dagcircuit.DAGCircuit") and [`QuantumCircuit`](/docs/api/qiskit/qiskit.circuit.QuantumCircuit "qiskit.circuit.QuantumCircuit") now shallow-copy any [`metadata`](/docs/api/qiskit/qiskit.circuit.QuantumCircuit#metadata "qiskit.circuit.QuantumCircuit.metadata") if the `copy_operations=True` argument is set in [`circuit_to_dag()`](/docs/api/qiskit/converters#qiskit.converters.circuit_to_dag "qiskit.converters.circuit_to_dag"), [`dag_to_circuit()`](/docs/api/qiskit/converters#qiskit.converters.dag_to_circuit "qiskit.converters.dag_to_circuit"), [`QuantumCircuit.to_dag()`](/docs/api/qiskit/qiskit.circuit.QuantumCircuit#to_dag "qiskit.circuit.QuantumCircuit.to_dag") or [`DAGCircuit.to_circuit()`](/docs/api/qiskit/qiskit.dagcircuit.DAGCircuit#to_circuit "qiskit.dagcircuit.DAGCircuit.to_circuit"). This transitively affects compilation functions such as [`PassManager.run()`](/docs/api/qiskit/qiskit.transpiler.PassManager#run "qiskit.transpiler.PassManager.run") and [`transpile()`](/docs/api/qiskit/compiler#qiskit.compiler.transpile "qiskit.compiler.transpile").

*   Added support for passing an iterable of operation types to [`DAGCircuit.op_nodes()`](/docs/api/qiskit/qiskit.dagcircuit.DAGCircuit#op_nodes "qiskit.dagcircuit.DAGCircuit.op_nodes"), for example `dag.op_nodes(op=(Measure, Reset))`. This allows collecting multiple instruction types in a single DAG iteration.

*   Updated [`QuantumCircuit.mcp()`](/docs/api/qiskit/qiskit.circuit.QuantumCircuit#mcp "qiskit.circuit.QuantumCircuit.mcp") so that it automatically selects the best decomposition technique based on the number of control qubits. This improves the performance of [`MCPhaseGate`](/docs/api/qiskit/qiskit.circuit.library.MCPhaseGate "qiskit.circuit.library.MCPhaseGate"), with circuit depth growing linearly in the number of qubits rather than quadratically as before. For gates with 2, 3, or 4 control qubits, the previous method is better in CNOT count, but for 5 or more control qubits, the new method is better.

*   Improve the default CX count in the definition of [`QuantumCircuit.mcx()`](/docs/api/qiskit/qiskit.circuit.QuantumCircuit#mcx "qiskit.circuit.QuantumCircuit.mcx") and [`MCXGate`](/docs/api/qiskit/qiskit.circuit.library.MCXGate "qiskit.circuit.library.MCXGate") with no ancilla qubits.

*   Added a compact exact decomposition for a singly-controlled [`RCCXGate`](/docs/api/qiskit/qiskit.circuit.library.RCCXGate "qiskit.circuit.library.RCCXGate"). Calling [`RCCXGate.control()`](/docs/api/qiskit/qiskit.circuit.library.RCCXGate#control "qiskit.circuit.library.RCCXGate.control") with one control now uses [`RC3XGate`](/docs/api/qiskit/qiskit.circuit.library.RC3XGate "qiskit.circuit.library.RC3XGate") and [`CSdgGate`](/docs/api/qiskit/qiskit.circuit.library.CSdgGate "qiskit.circuit.library.CSdgGate"), requiring 8 CX gates and 11 T or Tdg gates without ancillas. This also reduces the synthesis cost of higher-level controlled circuits containing RCCX gates, such as controlled modular adders.

*   Added [`ParameterExpression.structurally_equal()`](/docs/api/qiskit/qiskit.circuit.ParameterExpression#structurally_equal "qiskit.circuit.ParameterExpression.structurally_equal"), which can be used to compare whether two expressions have equal internal structures. This is mostly useful for testing Qiskit itself.

*   Added a `label` argument to single-gate instruction methods on [`QuantumCircuit`](/docs/api/qiskit/qiskit.circuit.QuantumCircuit "qiskit.circuit.QuantumCircuit") that previously did not expose one. This lets labels be set directly when adding these gates to a circuit using a method call (e.g. `circuit.cp(..., label=...)`).

*   Added a `label` argument to the [`RVGate`](/docs/api/qiskit/qiskit.circuit.library.RVGate "qiskit.circuit.library.RVGate") constructor.

*   Added a new [`ParameterExpression.simplify()`](/docs/api/qiskit/qiskit.circuit.ParameterExpression#simplify "qiskit.circuit.ParameterExpression.simplify") method that returns an algebraically simplified copy of the expression using the native symbolic engine. It collapses cancelling terms such as `a + b - a - b` to zero.

<span id="relnotes-2-6-0-openqasm-features" />

### OpenQASM Features

*   The OpenQASM 2 importer ([`qasm2.load()`](/docs/api/qiskit/qasm2#qiskit.qasm2.load "qiskit.qasm2.load") and [`qasm2.loads()`](/docs/api/qiskit/qasm2#qiskit.qasm2.loads "qiskit.qasm2.loads")) can now handle arbitrarily deep classical expressions. They no longer issue [`RecursionError`](https://docs.python.org/3/builtins/exceptions.html#RecursionError) based on the system recursion limit ([`sys.getrecursionlimit()`](https://docs.python.org/3/library/sys.html#sys.getrecursionlimit)).

<span id="relnotes-2-6-0-qpy-features" />

### QPY Features

*   QPY format version 18 significantly decreases the data size for most [`ClassicalRegister`](/docs/api/qiskit/circuit#qiskit.circuit.ClassicalRegister "qiskit.circuit.ClassicalRegister") and [`QuantumRegister`](/docs/api/qiskit/circuit#qiskit.circuit.QuantumRegister "qiskit.circuit.QuantumRegister") objects in a [`QuantumCircuit`](/docs/api/qiskit/qiskit.circuit.QuantumCircuit "qiskit.circuit.QuantumCircuit"). The constant overhead for registers has increased by 1 byte, but then in the worst case for each bit contained in the register the overhead has decreased from 8 bytes per bit in the register to 4 bytes per bit in the register. In the common case where the registers are added to the circuit contiguously the space requirement goes from 8 bytes per bit to 4 bytes total to represent the register.

<span id="relnotes-2-6-0-quantum-information-features" />

### Quantum Information Features

*   The [`SparseObservable`](/docs/api/qiskit/qiskit.quantum_info.SparseObservable "qiskit.quantum_info.SparseObservable") has a new method [`to_matrix()`](/docs/api/qiskit/qiskit.quantum_info.SparseObservable#to_matrix "qiskit.quantum_info.SparseObservable.to_matrix"). This method returns the dense matrix representation of the observable. Its reduced time complexity is $O(4^n)$ where $n$ is the number of qubits. See the Python API docs for details.

### Synthesis Features

*   Added [`synth_mcx_n_dirty_m15()`](/docs/api/qiskit/synthesis#qiskit.synthesis.synth_mcx_n_dirty_m15 "qiskit.synthesis.synth_mcx_n_dirty_m15"), which implements Maslov’s Clifford+T-friendly dirty-ancilla MCX construction. It uses one ancilla for three or four controls and $\lceil(k - 2) / 2\rceil$ ancillas for larger gates.

*   The clean-ancilla [`synth_mcx_n_clean_m15()`](/docs/api/qiskit/synthesis#qiskit.synthesis.synth_mcx_n_clean_m15 "qiskit.synthesis.synth_mcx_n_clean_m15") implementation now also uses $\lceil(k - 2) / 2\rceil$ ancillas instead of $k - 2$, without changing its T or CX counts. Thus, [`QuantumCircuit.mcry()`](/docs/api/qiskit/qiskit.circuit.QuantumCircuit#mcry "qiskit.circuit.QuantumCircuit.mcry") with `mode=None` can automatically select `basic` mode when at least $\lceil(k - 2) / 2\rceil$ clean ancillas are available.

*   Added a new plugin, [`PauliEvolutionSynthesisMcts`](/docs/api/qiskit/qiskit.transpiler.passes.synthesis.hls_plugins.PauliEvolutionSynthesisMcts "qiskit.transpiler.passes.synthesis.hls_plugins.PauliEvolutionSynthesisMcts"), for synthesizing [`PauliEvolutionGate`](/docs/api/qiskit/qiskit.circuit.library.PauliEvolutionGate "qiskit.circuit.library.PauliEvolutionGate") objects. The implementation combines ideas from the papers *MonteQ: A Monte Carlo Tree Search Based Quantum Circuit Synthesis Framework* by Machiya et al. ([https://arxiv.org/abs/2604.19029](https://arxiv.org/abs/2604.19029)) and *Faster and shorter synthesis of Hamiltonian simulation circuits* by de Brugière et al. ([https://arxiv.org/abs/2404.03280](https://arxiv.org/abs/2404.03280)).

    Compared to the default plugin, [`PauliEvolutionSynthesisDefault`](/docs/api/qiskit/qiskit.transpiler.passes.synthesis.hls_plugins.PauliEvolutionSynthesisDefault "qiskit.transpiler.passes.synthesis.hls_plugins.PauliEvolutionSynthesisDefault"), [`PauliEvolutionSynthesisMcts`](/docs/api/qiskit/qiskit.transpiler.passes.synthesis.hls_plugins.PauliEvolutionSynthesisMcts "qiskit.transpiler.passes.synthesis.hls_plugins.PauliEvolutionSynthesisMcts") typically requires more runtime but often produces higher-quality circuits. It is also significantly faster than [`PauliEvolutionSynthesisRustiq`](/docs/api/qiskit/qiskit.transpiler.passes.synthesis.hls_plugins.PauliEvolutionSynthesisRustiq "qiskit.transpiler.passes.synthesis.hls_plugins.PauliEvolutionSynthesisRustiq") while generally achieving better synthesis results.

    The quality of the generated circuits can be further improved by increasing the `num_simulations` option, at the cost of additional runtime. This overhead can be partially mitigated by executing simulations in parallel.

*   Added three synthesis functions for multi-controlled phase gates. [`synth_mcp_noaux_v24()`](/docs/api/qiskit/synthesis#qiskit.synthesis.synth_mcp_noaux_v24 "qiskit.synthesis.synth_mcp_noaux_v24") uses the newer no-auxiliary decomposition based on multi-controlled RZ gates, and is the better choice for up to 4 control qubits. [`synth_mcp_noaux_sp22()`](/docs/api/qiskit/synthesis#qiskit.synthesis.synth_mcp_noaux_sp22 "qiskit.synthesis.synth_mcp_noaux_sp22") implements the linear-depth strategy from da Silva et al. and is used for 5 or more control qubits. [`synth_mcp_noaux_default()`](/docs/api/qiskit/synthesis#qiskit.synthesis.synth_mcp_noaux_default "qiskit.synthesis.synth_mcp_noaux_default") is a dispatcher that selects between these two methods according to the number of control qubits.

*   Added a synthesis function for multi-controlled X gates with no ancilla qubits, [`synth_mcx_noaux_sp22()`](/docs/api/qiskit/synthesis#qiskit.synthesis.synth_mcx_noaux_sp22 "qiskit.synthesis.synth_mcx_noaux_sp22") that implements the linear-depth strategy from da Silva et al. This method provides better CX counts than [`synth_mcx_noaux_v24()`](/docs/api/qiskit/synthesis#qiskit.synthesis.synth_mcx_noaux_v24 "qiskit.synthesis.synth_mcx_noaux_v24"). Note that although this synthesis method grows quadratically in the number of controls, while the method in [`synth_mcx_noaux_hp24()`](/docs/api/qiskit/synthesis#qiskit.synthesis.synth_mcx_noaux_hp24 "qiskit.synthesis.synth_mcx_noaux_hp24") grows linearly in the number of controls, it still yields better CX counts where $n \leq 32$.

<span id="relnotes-2-6-0-transpiler-features" />

### Transpiler Features

*   Added an `approximation_degree` parameter to the [`CommutativeCancellation`](/docs/api/qiskit/qiskit.transpiler.passes.CommutativeCancellation "qiskit.transpiler.passes.CommutativeCancellation") transpiler pass. The parameter accepts a floating-point value between `0` and `1` (with a default `1.0`). This parameter is forwarded to the underlying commutation analysis for identifying gates that can be cancelled. The preset pass managers pass `pass_manager_config.approximation_degree` to [`CommutativeCancellation`](/docs/api/qiskit/qiskit.transpiler.passes.CommutativeCancellation "qiskit.transpiler.passes.CommutativeCancellation"), using `1.0` when the config value is `None`.

*   Added the `mcx.n_dirty_m15` high-level synthesis plugin. The default MCX synthesis plugin selects it for T-count optimization with three or more controls, and for two-qubit-count optimization with four or more controls, when enough dirty ancillas are available and no higher-priority clean-ancilla method applies. It can also be selected explicitly using [`HLSConfig`](/docs/api/qiskit/qiskit.transpiler.passes.HLSConfig "qiskit.transpiler.passes.HLSConfig"), for example as `HLSConfig(mcx=["n_dirty_m15"])`. The plugin requires $\lceil(k - 2) / 2\rceil$ clean or dirty ancillas for $k \geq 4$, and one ancilla for $k = 3$.

*   Added a new high-level synthesis plugin [`MCXSynthesisNoAuxSP22`](/docs/api/qiskit/qiskit.transpiler.passes.synthesis.hls_plugins.MCXSynthesisNoAuxSP22 "qiskit.transpiler.passes.synthesis.hls_plugins.MCXSynthesisNoAuxSP22") for the synthesis of [`MCXGate`](/docs/api/qiskit/qiskit.circuit.library.MCXGate "qiskit.circuit.library.MCXGate") with no ancilla qubits.

*   Added a new `optimization_level` argument to the [`HighLevelSynthesis`](/docs/api/qiskit/qiskit.transpiler.passes.HighLevelSynthesis "qiskit.transpiler.passes.HighLevelSynthesis") transpiler pass. This allows the pass to select synthesis methods that can produce more optimized circuits at the expense of increased runtime.

*   Added the [`PauliEvolutionSynthesisMcts`](/docs/api/qiskit/qiskit.transpiler.passes.synthesis.hls_plugins.PauliEvolutionSynthesisMcts "qiskit.transpiler.passes.synthesis.hls_plugins.PauliEvolutionSynthesisMcts") plugin to the default synthesis plugin for [`PauliEvolutionGate`](/docs/api/qiskit/qiskit.circuit.library.PauliEvolutionGate "qiskit.circuit.library.PauliEvolutionGate"). The plugin may be selected when `optimization_level >= 2` and the target has all-to-all connectivity.

*   Added a new method [`SparseObservable.contains_projectors()`](/docs/api/qiskit/qiskit.quantum_info.SparseObservable#contains_projectors "qiskit.quantum_info.SparseObservable.contains_projectors") that returns whether the observable contains any projector terms.

*   [`transpile()`](/docs/api/qiskit/compiler#qiskit.compiler.transpile "qiskit.compiler.transpile") now accepts a [`Target`](/docs/api/qiskit/qiskit.transpiler.Target "qiskit.transpiler.Target") instance as the second positional argument (the `backend` parameter). When a [`Target`](/docs/api/qiskit/qiskit.transpiler.Target "qiskit.transpiler.Target") is passed this way, it is treated as if it had been passed via the `target` keyword argument, consistent with the existing behaviour of [`generate_preset_pass_manager()`](/docs/api/qiskit/qiskit.transpiler.generate_preset_pass_manager "qiskit.transpiler.generate_preset_pass_manager"). This allows users to write:

    ```python
    tqc = transpile(circuit, target)
    ```

    instead of:

    ```python
    tqc = transpile(circuit, target=target)
    ```

    A [`TypeError`](https://docs.python.org/3/builtins/exceptions.html#TypeError) is raised if a [`Target`](/docs/api/qiskit/qiskit.transpiler.Target "qiskit.transpiler.Target") is passed positionally and `target` is also specified as a keyword argument. <span id="relnotes-2-6-0-miscellaneous-upgrade-notes" />

### Miscellaneous Upgrade Notes

*   The use of [`multiprocessing`](https://docs.python.org/3/library/multiprocessing.html#module-multiprocessing) with [`parallel_map()`](/docs/api/qiskit/utils#qiskit.utils.parallel_map "qiskit.utils.parallel_map") to run Python code in parallel on Linux has been disabled by default. This also changes the default multiprocessing behavior for functions that internally use [`parallel_map()`](/docs/api/qiskit/utils#qiskit.utils.parallel_map "qiskit.utils.parallel_map") such as [`transpile()`](/docs/api/qiskit/compiler#qiskit.compiler.transpile "qiskit.compiler.transpile") and [`PassManager.run()`](/docs/api/qiskit/qiskit.transpiler.PassManager#run "qiskit.transpiler.PassManager.run"). In previous releases on Linux systems it would default to running in parallel; however, this has proven to be unreliable especially when mixing threading with multiprocessing. This could result in deadlocks when downstream provider packages, such as `qiskit-ibm-runtime`, would use async Python. In general the importance of leveraging multiprocessing for performance has significantly diminished since Qiskit 1.0 as more of the library has enabled parallelism via Rust and multithreading which was already mutually exclusive with Python multiprocessing. If you would like to continue to use multiprocessing with [`parallel_map()`](/docs/api/qiskit/utils#qiskit.utils.parallel_map "qiskit.utils.parallel_map") or other Qiskit functions using it internally you can explicitly opt-in to enable multiprocessing. To explicitly enable multiprocessing on Linux (or any platform) you can either set an explicit start method to `"fork"` or `"forkserver"` using [`multiprocessing.set_start_method()`](https://docs.python.org/3/library/multiprocessing.html#multiprocessing.set_start_method) (explicitly setting `"spawn"` still disables multiprocessing by default because of the extra overhead and complexities associated with it and you’ll need to enable multiprocessing with spawn using the other two options), set the environment variable `QISKIT_PARALLEL=TRUE`, or set `parallel` to `True` in your [user configuration file](/docs/guides/configure-qiskit-local#user-configuration-file).

<span id="relnotes-2-6-0-performance-improvements" />

### Performance Improvements

*   [`qk_circuit_barrier()`](/docs/api/qiskit-c/qk-circuit#qk_circuit_barrier "qk_circuit_barrier") no longer re-allocates a temporary buffer to view the `qubits` array.

*   Improves runtime performance of the [`add_register()`](/docs/api/qiskit/qiskit.circuit.QuantumCircuit#add_register "qiskit.circuit.QuantumCircuit.add_register") method on [`QuantumCircuit`](/docs/api/qiskit/qiskit.circuit.QuantumCircuit "qiskit.circuit.QuantumCircuit"). Consequently, this change improves performance when creating [`QuantumCircuit`](/docs/api/qiskit/qiskit.circuit.QuantumCircuit "qiskit.circuit.QuantumCircuit") as well. Generally, the time complexity of checking register name presence was reduced to $O(1)$ from $O(n)$. This was achieved by removing redundant error checking.

*   Improved the runtime performance of [`synth_qft_full()`](/docs/api/qiskit/synthesis#qiskit.synthesis.synth_qft_full "qiskit.synthesis.synth_qft_full") by migrating the implementation to Rust. Benchmarks show speedups ranging from \~9x at 5 qubits to \~30x at 200 qubits, and \~11x at 1000 qubits. See [#16789](https://github.com/Qiskit/qiskit/pull/16789).

See [#16835](https://github.com/Qiskit/qiskit/pull/16835).

*   QPY version 18 now stores each [`ParameterVector`](/docs/api/qiskit/qiskit.circuit.ParameterVector "qiskit.circuit.ParameterVector") once per circuit payload, in a new `PARAMETER_VECTOR_TABLE`. QPY now avoids repeating the vector’s name and size for each element, and instead refers to each by index. An element now occupies 10 bytes instead of 34 plus the length of the vector’s name. For example: a circuit using a 100-element vector is now around 29% smaller.

*   QPY version 18 narrows the bit-term elements of the `SPARSE_OBSERVABLE` payload from `uint16_t` to `uint8_t`, reducing the representation for [`SparseObservable`](/docs/api/qiskit/qiskit.quantum_info.SparseObservable "qiskit.quantum_info.SparseObservable") instances in QPY by 2 bytes per term in the observable.

*   Improved the performance of compilation into Clifford+T basis sets (for example, using [`generate_preset_clifford_t_pass_manager()`](/docs/api/qiskit/qiskit.transpiler.generate_preset_clifford_t_pass_manager "qiskit.transpiler.generate_preset_clifford_t_pass_manager")) by removing transpiler passes that have little or no impact on the quality of the resulting circuit. See [#16406](https://github.com/Qiskit/qiskit/pull/16406) for more details.
